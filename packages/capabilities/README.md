Public APIs:

```ts
DOMAIN_TOOLS: { name: string; description: string; parameters: JSONSchema }[]
handleDomainTool(name: string, args: unknown, ctx: DomainContext): Promise<unknown>
executeDomainOperation(op: Operation, ctx: DomainContext): Promise<unknown>
reconcileDomainOperation(op: Operation, ctx: DomainContext): Promise<Reconciliation>
```

`DomainContext` follows [the shared integration contract](../../docs/integration-contract.md): `threadId`, `signal`, `resolveResource(id,path?,write?)`, `publishData(value,provenance)`, `prepareOperation(kind,args,resourceIds,preconditions,description)`, and `progress(message,counts?)`. The host also supplies `withResource<T>(id,path,write,action)` to validate the original grant while a native filesystem guard remains held through `action`. Embedders without that optional method receive a guarded pathname fallback and still own grant/storage validation. Dispatch requires matching `threadId`, `approved:true`, `status:"running"` and exact resource IDs. Preparation never mutates source/export resources.

On local Windows, a fixed application-owned PowerShell helper uses system Win32 APIs, JSON stdin and no command interpolation, profiles, elevation or native package install. It pins every ordinary directory ancestor against rename and reparse mutation, verifies opened final paths, and pins existing read/SQLite files against replacement. File data/size checks use one opened handle. Redirected `pi`/`artifacts` storage roots, multiple hardlinks, alternate streams and nonlocal/device namespaces fail closed. The original abort signal remains effective before acquisition and I/O; completed effects are not relabelled cancelled after the callback returns. PowerShell/guard failure and unsupported platforms fail closed. These guards can temporarily block concurrent namespace edits. They protect host file operations, not arbitrary accesses by child processes or approved project code; this is not an OS sandbox.

SQLite inspection/preparation reads a bound snapshot into an exclusive temporary directory and checks the original hash again afterward. Execution pins the selected database and an exclusively created empty rollback journal before starting the real worker. `journal_mode=TRUNCATE` preserves that journal inode through COMMIT. Preexisting journal/WAL/SHM paths are rejected; cleanup compares exact opened identities and retains nonempty hot journals or replacement files. Worker cancellation remains `OPERATION_OUTCOME_UNKNOWN` for execution, including COMMIT races.

Git read tools support ordinary local `.git` directories in v1. The helper holds working-tree/metadata directories and files through launch/process completion and rejects reparse points, hardlinks, external gitdir/commondir layouts, object alternates and local include/includeIf or executable filter sections. A 10,000-entry/64-level tree bound fails closed, including large or linked ignored directories. Worktrees/shared metadata are unsupported. Explicit git/worktree paths, disabled submodule traversal, external attributes/ignore/mailmap/signature processing and lazy fetching keep reads within this bounded mode; ordinary status/diff/log remain available. The working-tree gate specifically prevents whole-repository diff from reading a protected file through a tracked parent junction. This does not constrain arbitrary filesystem access by approved repository test code.

Source reads publish actual values and SHA-256 provenance through `ctx.publishData`, returning a `DataRecord`. Data can be bound across categories; see [the frontend props contract](../ui-catalog/README.md). Knowledge synthesis explicitly labels its sources, not independent verification. Repository status/diff/log publish actual process output and exit codes; external diff, textconv, fsmonitor, inherited Git config overrides and interactive prompts are disabled.

Prepared operation kinds are `file.replace`, `repository.test`, `database.transaction`, `database.migration`, `pdf.export`. Only `executeDomainOperation` writes source/export resources. File replacement uses a matching before SHA-256 and final guarded recheck, an exclusive temporary file and fsync. The native helper verifies the opened temporary file's exact identity/hash, denies concurrent writes/deletion and renames that same opened object within its pinned parent. It also verifies the destination's identity/hash through one opened handle and denies in-place writes until replacement finishes. External atomic saves can still replace the destination pathname during this interval; this is not an atomic compare-and-replace guarantee. The host serializes prepared operations service-wide; competing editors must be paused for an exact approved replacement. Temporary cleanup deletes by opened identity and preserves replacement inodes. No staging/commits are performed on user repositories.

Test recipes execute precisely `process.execPath --test -- <one named .test.js/.mjs/.cjs/.ts file>` with shell disabled and a 120-second timeout. The operation description discloses that approval executes that file's code with local-user privileges; it is not an OS sandbox. Results are `{status,exitCode,signal,cancelled,timedOut,stdout,stderr,truncated}` and never invent passing tests. Cancellation kills the Windows tree with `taskkill /PID <pid> /T /F`; POSIX uses the process group. Host must map nonzero exit, cancellation or timeout to a failed/cancelled operation and retain the result.

SQLite uses installed `node:sqlite` in a worker that can be terminated for cancellation/timeout. Node >=24.10 with `setAuthorizer` is required for these external-database tools (current environment: 24.14). Older Node fails closed. Select an external, closed rollback-journal DB of at most 256 MiB; active WAL/journal databases are deliberately unsupported. Inspection opens read-only and reports schema, integrity, real count and bounded rows. Every DML statement needs exact `expectedChanges`; migration permits CREATE/ALTER/DROP in addition. Preparation compiles statements individually against the current schema; migrations depending on a newly created table/column need separate prepared operations. One statement per entry; comments/embedded semicolons/CTEs/triggers/virtual/temp tables/ATTACH/DETACH/PRAGMA/extensions are unsupported. The SQLite authorizer also denies cross-database/unsafe functions. Execution uses BEGIN IMMEDIATE, before SHA-256 recheck, integrity/foreign-key checks and rollback on a count mismatch. Counts distinguish DML changes from schema statements. Cancellation/timeout during execution or an error after COMMIT raises `HarnessError("OPERATION_OUTCOME_UNKNOWN", ...)`; root must retain `unknown` status and reconcile, since cancellation racing COMMIT is not proof of rollback.

PDF inspection uses installed `pdf-lib`: page dimensions, supported field values/options, best-effort text operators and explicit limitations. No OCR, encrypted PDFs, XFA, complete custom-font text decoding, certificate signing, email or remote delivery. Supported fills are text fields, checkboxes, dropdowns, option lists and radio groups with type/option checks. Editing PDFs containing certificate signature fields is refused. Visual signatures are `{kind:"typed",text,page,x,y,width,height}` or `{kind:"drawn",points:[{x:0..1,y:0..1}],page,x,y,width,height}`; page is 1-based and placements use PDF points from the bottom-left, within an unrotated page. Drawn point coordinates are normalized top-left within the placement box. New export paths must end `.pdf`; writes use exclusive creation and never overwrite an export or original. Source and prepared output hashes are retained as preconditions.

`reconcileDomainOperation` is read-only and never retries or prepares a retry. It returns `{status:"succeeded"/"failed"/"cancelled"/"unknown",basis:"postcondition"/"recorded-result"/"unresolved",result?,message}`. It confirms a file matching replacement bytes, a PDF matching the prepared export SHA, a DB matching a recorded committed result version plus current integrity, or recorded process exit evidence. Matching before hashes, unrelated edits, missing exports and unrecorded database/test outcomes stay `unknown`. A postcondition proves current bytes, not which actor wrote them. Root should persist this evidence and expose unresolved outcomes to the user.

Disposable fixtures: `pnpm fixtures:create <NEW-destination>` creates real local Git history/conflict/test files, source documents, an editable PDF and external SQLite DB exclusively inside that directory. It refuses existing destinations; it never touches existing user projects. Evaluation commands and honest pending gates are documented in [evals/README.md](../../evals/README.md).
