# UI source guard

Run `pnpm test:ui-guard` for the positive/negative fixtures, then `pnpm lint:ui` for all public first-party sources. CI runs both after the locked dependency install. `pnpm lint:ui --json` prints the source inventory, new violations, matched legacy occurrences and retired entries. Exit codes: 0 passes, 1 policy violations, 2 invalid arguments/configuration/syntax.

`scripts/ui-guard.ts` uses the installed TypeScript compiler and checker, not a source-text blacklist. The numeric rule follows rendered JSX child values, `children` props, component returns, local render aliases, arrays and array render callbacks, and imported React factories/portals. It checks numeric type aliases, constrained numbers, optional values, unions, enums and bigint zero. Explicit comparisons, boolean coercion and known nonzero literal types pass. Conditional tests, ordinary function arguments and non-rendered JSX attributes/events are not child sinks. `||` can discard a scalar zero; it cannot discard zero entries inside a truthy array. Unresolved/any gate types require an explicit boolean too.

The architecture rule rejects native select/dialog/popover construction, overlay roles, overlay surface classes, React portal aliases, attribute object spreads, fixed/absolute overlay geometry, and static DOM HTML/style sinks outside named shared primitives. Script/JSX and inline HTML JavaScript are parsed as TypeScript syntax; HTML start tags are parsed as JSX and CSS blocks/declarations are tokenized. Inline script findings map back to the original HTML location. Syntax errors in script sources fail the command. Arbitrary computed markup or runtime-generated class/style values cannot be proven by static analysis; those require review and later geometry/runtime checks.

The scan discovers files on disk, including new untracked files, under `apps/web`, `apps/desktop`, `packages`, and every first-party `plugins/*/src`. It covers TS/TSX/JS/JSX/MJS/CJS, HTML and CSS. Dependency/build output and declaration files are not implementation inputs. Native Electron OS dialogs/window APIs are not DOM overlays; desktop source is still scanned. Generated third-party application payloads remain governed by the existing receiver policy, not promoted to trusted UI by this guard.

Only the individually named shared primitive implementation/style files in `primitiveImplementations` are approved. Numeric checks still apply inside those files. Adding another file to `packages/ui-shell` grants no exemption. Consumers are recognized by their resolved imported component declaration, including aliases; a similarly named local component grants no approval.

`ui-overlay-legacy.json` records each existing candidate separately by path, source location, syntax fingerprint, evidence and migration reason. These entries preserve legacy browser behavior while controls migrate; they are not approved primitives. Conservative geometry candidates that are not dropdowns/popovers/modals carry an explicit retained-geometry reason. No directory or entire legacy file is exempt. Matching consumes one inventory entry, so adding even an identical second occurrence in the same file fails. Changed opening attributes or CSS declarations also require review. Numeric gates cannot be grandfathered. Removed occurrences are reported as retired and confer no allowance elsewhere.

There is no baseline update/regeneration command. A migration should remove its entry. A necessary new exception requires a narrowly identified occurrence, a concrete reason and independent review; do not replace the inventory with the latest scan. Coordinate primitive-file additions with the control owner. This source guard does not establish native behavior, visual acceptance, DPI, live-provider behavior or screenshot geometry acceptance.
