## OBJECTIVE
`apps/web/src/App.tsx` uses one workspace error string: a later error overwrites the earlier one and Refresh repeats bootstrap, snapshot loading, and model loading. Preserve concurrent failures and recover the failed operation without refreshing unrelated state.

## REQUIREMENTS / APPROVED DESIGN
- Match the app's light/dark neutral surfaces, subtle borders, compact controls, red error icon, and compact right-aligned stack below the toolbar. Keep the composer usable.
- Each error is independently dismissible. Offer scoped Retry when the original operation can safely be retained; never replay an unknown mutation or new-consent action just to provide a button.
- During retry, update the same card to a disabled spinner/Retrying state; other notifications remain actionable. Repeated identical failures update that card, not the entire stack. Retry failure remains visible; success shows an in-place receipt, holds for 2 seconds, then leaves (pause on hover/focus).
- Newest errors first; errors never auto-expire. **Approval addition:** show at most 3 cards by default and collapse older ones into one `+N more` row. Expanding must retain access to older errors without an unbounded overlay (bounded scroll area, collapse control).
- Enter: fade and translate down 8px, 200ms with existing enter easing. Exit: fade/translate up 8px, 160ms; smooth removal using existing 140ms remove timing. Respect app and OS Reduced/Off settings: no translations or spinning; Off changes immediately.
- Announce new failures without stealing focus; name each Retry/Dismiss; support keyboard operation and preserve access to overflow. Dismissing a notice does not cancel an in-flight operation or resurrect it on completion.
- Recovery ownership (clarified during review, T02/T03): distinguish each concurrently mounted conversation, even for identical messages. Release only that owner’s startup/sync recovery entries when its effect is disposed; reopening starts a fresh recovery, never a stale Retry that claims success without opening the current conversation. Ignore initial read failures completing after owner teardown. Other owners’ notices remain.
- Visibility/lifetime (T01/T03): Hide removes the closed portal so production DesktopBrowserSlot bounds are restored; hidden non-portal cards keep success/exit timers running. Show reopens remaining notices. Notification state is not erased by hiding.
- No server/contracts/storage changes, automatic mutation replay, unrelated refactors, or production behavior claimed from mockups.

### Approved compact revision
- Target width 336px, 56px minimum card height, 8px gaps, inline 28px Retry/Dismiss controls, two lines of meaningful text. Preserve existing Gen typography and themes rather than applying marketing-page font or palette defaults.
- Remove redundant heading, timestamps, extra recovery prose, separate action rows and bulk-dismiss chrome from the earlier mockups; retain individual controls and the required `+N more` row.
- Default 3-card stack is approximately 222px high including overflow. Expanded older errors use a 312px capped scroll area with Show fewer. Retry and success keep stable card height and position. Long real errors must wrap rather than disappear; dimensions are minimums, not clipping constraints.
- These are static proposals, not production behavior. Compact dimensions approved. Add a solid surface and subtle shadow; provide a persistent Show/Hide errors control in its own in-flow toolbar row so the user can expose all covered content without dismissing errors. Keep notification lifetime independent of visibility.
