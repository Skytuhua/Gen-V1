# Edit the last prompt and rerun

## META

- **Repository:** `skytuhua-org/Gen-V1` · **Plan revision:** 1 · **Date:** 2026-11-21 · **Size:** medium.
- **Baseline:** [main at 4ca1134ae1e4f354064457cb5664b545712da4a9](https://github.com/skytuhua-org/Gen-V1/commit/4ca1134ae1e4f354064457cb5664b545712da4a9), inspected from a checkout.
- **Status and related work:** No matching issue or PR found in the repository title inventory (including closed items) or targeted searches for editing a prompt or message. [#576](https://github.com/skytuhua-org/Gen-V1/issues/576) concerns a native fork API for review/idle work, not this feature and not a dependency. Current Send, Retry send, and History/Inspect remain separate; the M14 ledger does not claim native forks are supported.
- **Provenance:** Batch 7, item 4 and scope note 4: after a turn ends, replace the latest sent user prompt with revised text, rerun in the same conversation, preserve the old reply as a collapsed earlier version, do not revert files, and exclude the replaced turn from model context without duplicating hidden context. Research: Claude Code checkpointing and the two Codex reports linked below.

## OBJECTIVE

A typo or changed instruction should not force the user to open a new task or add a corrective turn that leaves contradictory instructions in the model's conversation. In an idle task the user can edit the most recent completed prompt and rerun it in place. The live transcript and next model request agree on which version is current. Earlier replies remain readable, survive restart, and never become model history merely because the user reveals them. The workspace and its file history are not rolled back.

## REQUIREMENTS

| ID | Requirement and observable boundary |
| --- | --- |
| R1 | Only the newest user prompt in an idle, writable Personal main conversation is eligible. An active, queued, stopping/tearing-down, interrupted, or unreconciled run cannot be edited. A stale tab, archived thread, newly sent prompt, or changed account/workspace cannot cause an edit to the wrong turn. No side, delegate, or plug-in mutation. |
| R2 | **Edit prompt** opens with the complete original text (not rendered Markdown, a clipped slice, or a compiled prompt). **Cancel** leaves the transcript, runtime, and independent unsent draft unchanged. **Rerun** requires changed nonblank text within existing Send limits, retains the task, model/account and reasoning level, and leaves existing Run/Stop behavior intact. Rejection keeps the edit text and old reply. |
| R3 | Once accepted, edited text becomes the single current prompt at that turn position. The previous prompt and reply are retained as a collapsed **Earlier version**; multiple edits are recoverable in reverse version order. Recovery means view and copy, not undoing a run or creating a named branch. Persistence and reconnect are required. |
| R4 | Model continuation starts at the genuine pre-turn boundary: earlier active context once, revised input once, superseded prompts, replies, and turn-owned tool/hidden material zero times. Apply this to repeats and later ordinary sends. Never silently degrade to a follow-up, transcript quote, or empty-history restart. |
| R5 | Do not revert files, re-execute old tools to reconstruct history, or delete/transplant approvals, receipts, checkpoint records, or artifacts. Show **Files are not reverted.** and a **File checkpoints** action that opens the same task's Changes → History when available. Fresh inference may see current files and request fresh tools under ordinary permissions. |
| R6 | Use existing theming, focus rings, owner/read-only handling, CSRF/session protection, pagination, and motion preferences. Give keyboard, screen-reader, light/dark, narrow pane, and reduced-motion users the same functionality; do not bind Enter on a multiline edit. Version data must not inflate ordinary snapshot/transcript payloads without bound or leak through another thread's cursor. |
| R7 | Keep the feature behind an off-by-default capability until the real Hermes source path and recovery are demonstrated. Unsupported runtime, missing trusted cut, multi-input/source-bound prompt, or incompatible older data gets an unavailable result, never a lossy fallback. Preserve ordinary send/retry and access to already stored versions when new editing is disabled. |

**Implementation choices proposed in this plan:** v1 uses the production Hermes main-thread path, a single plain-text handled input for a successfully settled turn, and an explicit in-place editor detached from the ordinary composer draft. No editing earlier prompts, cross-thread recovery, picking a version to promote, supporting merged follow-ups or source/excerpt/attachment/skill-bound inputs until their full custody is modeled, or writing any file-restore path. Do not infer plain text from the absence of client chips: verify the accepted input and authoritative runtime run records. Where legacy records cannot prove a cut, the next supported completed turn can establish one for subsequent editing. Queued or overlapping background work is excluded when it can affect the same owner; do not introduce a global idle rule that supersedes normal foreground concurrency limits.

## DESIGN

### Control flow and contracts

Use additive, versioned contracts (names below proposed). Keep immutable attempt records and one active pointer per logical turn; don't rewrite old message/run IDs. The logical turn is anchored to the first accepted prompt's transcript position; associate prompt, outbox input, terminal run, visible reply fragments, and any context attribution by authoritative IDs rather than timestamps, roles alone, or adjacency. Preserve activities, artifacts, file changes, usage, and approval/audit records independently; do not relabel an old operation as belonging to the replacement. Dependent split/detached views must use the same logical owner and pointer.

- **Turn anchor:** host-only `{threadId, turnId, originalMessageId, activeVersionId, revision, cutId}`. Immutable per-attempt rows carry version ID/number, source prompt/message ID, input ID, run ID when admitted, status, and reply IDs (or equivalent indexed associations). Cut custody is not renderer data. A small owner-bound read head exposes editable message ID, opaque edit revision, and availability; row projection identifies only the active version and previous-version count. Do not turn original prompt text into an extra model input.
- **Mutation:** proposed `message.editRerun` via the existing authenticated command, payload strictly `{messageId, expectedRevision, content}`, with command ID for receipt retries; return `{turnId, versionId, messageId, inputId}`. No client-supplied run/account/cut/path/context. Reuse the existing Send model/account gates, reasoning level, input validator, request-custody authority, workspace/trust checks, foreground limits, run epoch and outbox delivery. Make eligibility and ordinary send/other owner mutations check the same per-thread admission fence. Check last writable/settled plain-text input, review/teardown, open gates and unresolved operations, account/project/workspace generations, and head revision before doing async preflight and again at atomic admission. Validate content without trimming internal whitespace. Reject blank, unchanged, oversized, unknown keys, cross-thread target, unsupported history and stale revision. Recheck actual acceptance by receipt on timeout or lost connection; the same ID and payload must return the same receipt, mismatched reuse must not mutate.
- **Acceptance point:** append the new attempt and durable outbox record, flip the active turn pointer, and publish a projection/invalidation with the receipt in one SQLite transaction. Use a durable generation ID for the replacement before dispatch. Before acceptance, any eligibility, authority, staging, or validation failure leaves the old pointer and runtime intact and preserves edit text. After acceptance, Stop or dispatch/runtime failure uses existing run teardown/reconciliation, clearly marks the **current** attempt stopped or failed, and leaves the previous version accessible. No automatic second inference or rollback to the old runtime. Use accepted input recovery rather than resubmitting the edit as a new message; if runtime ownership or dispatch certainty is lost, block resume until reconciled. Never mark work handled solely because a replacement generation was created.
- **Read path:** project the active attempt at its stable turn anchor for snapshots, bounded history, incremental updates, and scoped reads, even if its physical row arrived last. Extend existing projection/revision semantics or force scoped resync on pointer changes; don't append the old active rows and new rows as simultaneous live transcript. Fetch earlier attempts on disclosure through a dedicated owner-scoped, no-store read in the Personal read route family; page attempt heads and reply content with bounded slices and opaque signed cursors. Keep archive permissions consistent with current transcript access, and reject stale/revoked/cross-owner cursors. For normal Conversation Find, search only active transcript and retain the existing loading/anchor behavior; expanded earlier versions may be read and copied explicitly, without polluting active find highlights. Treat search/export/History/quotes and any core or runtime migration reader according to purpose: active conversation consumers see active projection, audit readers keep originals, and showing an earlier version does not create a model input. Verify update/reconnect converges in the default and optional read models.

### Native context custody and recovery

Use an **immutable native pre-turn cut** and an isolated, app-owned **native generation** for replacement, not a product session fork. Make this a prerequisite to enabling the mutation. A cut captures exactly the effective native conversation state immediately before an eligible prompt enters Hermes, including earlier pinned native context/compaction needed for continuation. Capture before first eligible sends (including empty-history start), through the host-owned wrapper under the existing run/owner fence. Persist the cut only on a valid settled association, bind it to thread, provider/account/model, workspace/grant, epoch, engine revision, and stable turn ID, and retain the original cut unchanged across edits of that turn. Never derive a cut by cutting at a string match or counting visible messages. Fail closed on missing/invalid, oversized, compacted-without-a-verifiable-boundary, or revoked context. Before enabling, demonstrate capture for a multi-turn case through the real worker; explicit display-history migration is insufficient.

- At rerun, stage a fresh native session namespace and exact cut under a host-generated opaque generation. Extend **both** adapter and worker path/owner validation, worker identity, provider/session continuation and input sidecar identity to match generation; prevent legacy fallthrough. A client cannot name files or inspect cuts. Audit every caller carrying `sessionPath` or opening input sidecars (history, recovery, compaction, checkpoints, review, tools, task pool); legacy paths still resolve for never-edited threads, and methods that cannot prove the active generation must report unsupported instead of resuming a superseded session. Reject symlinks, traversal and cross-account/cross-thread binding. Use the existing private data root, bounded I/O and atomic writes; do not put prompts, prefix data, source paths, or credentials in receipts or diagnostics.
- Instantiate the worker/agent and any remote continuation afresh for the new generation; load only the authorized cut, not previous run buffers, model conversation IDs, tool call caches, compaction output, or stale compiled input. Rebuild current authorized instructions, tool manifest, and request input once through normal custody. A cut may contain earlier native role/tool messages, but it is never concatenated into the new user prompt and never executes earlier tools. Do not trust bookkeeping based on the first transport edge: inspect the actual final inference envelope.
- Audit `requestBasis`, request compiler sources, Plan/memory and/or reusable derived context. Apply the active-version filter wherever per-turn content is directly supplied or summarized into hidden context; use actual provenance. Recalculate from independently authorized sources with the same normal layering, and reject editing under a configuration where a turn-owned materialization cannot be excluded without dropping mandatory earlier context. Do not redact unrelated files or intentional user-provided independent notes merely because they contain the same text. Retain receipts for audit, never feed superseded receipts as chat history. The standard later send must resume the replacement generation and not implicitly reselect the legacy/native predecessor.
- Crash/restart: store the generation/cut references and dispatch state in durable host records, ensure a staged generation without a commit cannot become active, and verify the exact generation when resuming an accepted-but-not-dispatched input. Distinguish that case from ambiguous partial dispatch. Keep old native state needed for recovery/audit, but never recover an active attempt by silently loading it. Bound new storage with existing profile ownership/cleanup policy: retain reusable cuts for editable turns and preserve earlier display versions while the conversation lives; unreferenced staging cleanup must not touch a committed or uncertain generation. Feature rollback disables new editing, not projection or generation-aware resumes. Downgrading to a binary that cannot interpret generation custody is not a supported transparent rollback: protect edited conversations from reopening in incompatible code, document recovery and test flag-off behavior before rollout.

### Visual and interaction specification

No separate design work is required before implementation. Put a quiet pencil and **Edit prompt** text in the latest eligible user row's action rail (same spacing and icon treatment as adjacent message actions); never depend on hover to discover it. Under a narrow pane, wrap the action rail and controls rather than hiding the label or causing horizontal scrolling. Use existing conversation padding/typography and tokenized foreground, muted foreground, surface, border, and focus colors in both themes. Enter edit mode in the same row with a bordered panel, **Edit prompt** label, full-width multiline textarea, the **Files are not reverted.** notice, quiet **File checkpoints** action, and a footer with **Cancel** and primary **Rerun**. Use ordinary Composer controls and focus styles, but don't replace Composer's independent draft, attachments, shortcuts or model controls.

On open focus the textarea with the caret at the end. Enter inserts a line break; keyboard users can tab to **Rerun** and activate it normally. Escape cancels only while the editor owns focus and when not composing via IME or submitting. Cancel returns focus to the opener; immediately queue focus to a stable status or new prompt action on accepted replacement, never to document body. Prevent submit/dismiss duplication while acknowledgement is pending and announce **Starting rerun…** in a polite status; show resync/conflict text inline and preserve the textarea so it can be copied. If the owner changes, do not transfer text or focus to another owner's input; scope any retained in-session edit state to its exact owner and captured revision. Do not disable normal outgoing features elsewhere; use existing host concurrency and errors. Reuse existing scroll-follow behavior only if following before submit; otherwise pin the visible anchor.

Under the active turn show a compact, neutral border-and-chevron disclosure labeled **Earlier version** (plural/count for several); default closed after admission and reload. Expanded attempts are marked **Version N · Earlier**, newest first, with original prompt and reply, copy controls, and bounded **Load more**. Use real button semantics with `aria-expanded` and `aria-controls`; hidden contents cannot receive focus; expanded content is not announced as new model output. Move focus back to the disclosure before hiding focused content. Navigation to File checkpoints opens the current owner at Changes → History without initiating a restore. If unavailable show the notice without an actionable link.

Animate entrance of editor/earlier-version contents with existing motion tokens consistent with a 140 ms ease-out opacity transition and up to 4 px vertical travel; rotate chevron 90 degrees over the same duration. Collapse content immediately for accurate focus and scroll measurement; do not animate height or scroll, add blur, delay command dispatch, or replay animation on ordinary polling. Reduced motion skips translation, rotation interpolation and opacity transition; end state and focus are identical. Respect form zoom, 320 px pane width, visible focus, high contrast, and theme contrast for muted text.
