## Objective

On a corporate network that requires an explicit proxy, a user can enter one HTTP(S) proxy and one bypass list in Settings instead of maintaining independent startup arguments and runtime environments. A supported provider's sign-in network calls, model/catalog calls, and the docked Browser's permitted public pages reach their destinations by the intended route; the Gen host and its loopback model broker remain reachable directly. Prove the chosen route from fixture traffic, not from a successful status code alone.

## Requirements and user flow

- One profile-wide setting, not per account, thread, machine-wide OS configuration, or synced preference. Default is **Not configured**, preserving present behavior for each network path. Scope is Gen-owned outbound provider HTTP(S) and the desktop Browser's public HTTP(S) traffic. System-browser pages opened for OAuth still use that browser's own network configuration; explain this if applicable. The setting does not change project terminals, Git, plugins, arbitrary tools, OS networking, installer/updater, or unrelated services.
- In **Settings → Models & Accounts → Network proxy**, enter a proxy URL, optionally including percent-encoded username/password, plus a comma-separated **Bypass list (NO_PROXY)**. Save explicitly; no requests based on unsaved text. A configured URL is always displayed without credentials; show **Credentials saved** separately. To rotate credentials, paste a replacement URL; to remove credentials while leaving the endpoint, select **Remove saved credentials** and Save. If the endpoint changes, do not carry the old endpoint's credentials forward. **Remove proxy** clears the endpoint, bypass list, and saved credentials after confirmation in the card; Cancel has no effects. Never expose a reveal/copy affordance for stored credentials.
- Proxy URL accepts `http://` or `https://`, host and optional port, root path only. No query, fragment, path payload, arbitrary schemes, or inline comments. An HTTPS proxy uses TLS to the proxy; target TLS and hostname verification remain enabled independently. Support explicit Basic proxy credentials supplied in the URL; refuse authenticated configuration when supported OS secret storage is unavailable. No plaintext fallback. Keep URL-edit input masked while entering a replacement and don't prefill stored credentials. Use actionable copy without echoing values.
- Common v1 bypass syntax: comma-separated case-insensitive exact host/IP, leading-dot domain suffix (apex and label-boundary subdomains), optional port, and IPv6 literals (bracketed with a port). Whitespace around entries allowed; canonicalize/deduplicate and reject unsupported rules such as wildcard, CIDR, schemes and paths with a field error, not silent broadening. Define the effective port from the destination scheme when not explicit. Show mandatory local bypass separately: `localhost` / `.localhost`, all IPv4 loopback, IPv6 loopback and IPv4-mapped loopback, plus Gen's approved local endpoint(s). It wins over stored settings and inherited proxy env; Browser local/private destinations are **blocked**, not made accessible by bypass.
- Saving governs subsequent host requests, newly admitted provider work/sign-in, and subsequent Browser navigations. Keep already-running work on its admitted revision until it ends; don't replay work, reroute an in-flight model stream, or cancel OAuth to apply a setting. An open Browser page can be reloaded to pick up the new route. If any target can't apply safely, clearly mark pending availability and let users retry; never silently switch configured external traffic to direct. When the proxy rejects auth, is unreachable, or fails TLS, show a short safe error and retain a reachable Settings/Remove path on loopback.
- No NTLM, PAC, WPAD, proxy discovery, SOCKS, enterprise certificate enrollment, network kill switch, Internet connectivity probe or automatic direct fallback. NTLM/PAC/WPAD are research notes only. Do not claim all vendors honor env vars or all enterprise proxies permit pinned tunnels: prove support per adapter and report restrictions.

## Design

### Profile policy, contracts and lifecycle

Proposed new files: `packages/core/network-proxy-settings.ts` (storage and writer), `packages/contracts/network-proxy.ts` (strict management DTOs), `apps/server/network-proxy-routes.ts`; no backing DB migration. Treat paths/DTOs in this section as proposed, not existing.

- A dedicated authenticated, same-profile, same-origin `GET /api/network-proxy`, `PUT /api/network-proxy` and `DELETE /api/network-proxy` sends `Cache-Control: no-store`. Use the current host request authorization; verify plugin/paired/remote callers cannot mutate or read this profile control. No proxy data from conversation/device sync or project configuration. Public response: `{revision, url: string|null, bypass: string[], hasCredentials, secretStorageAvailable}` plus bounded applied/pending status only if needed to represent runtime/native state. Public URL never contains userinfo. Mutation accepts `{baseRevision, url, bypass, clearCredentials?: true}` or `{baseRevision}` on DELETE. Conflicting auth actions, oversized input, malformed percent escapes/control characters (including decoded), and stale revisions fail with safe fixed field messages. Set explicit request/document limits (e.g. URL 4 KiB, 64 entries, total list 4 KiB); parse/normalize once, check lengths after decoding, and never echo an untrusted string or structured parser error to API logs.
- One writer serializes revisions; write a private versioned profile document atomically (protected credential blob and sanitized endpoint/bypass in the same transaction, no plaintext or split-brain updates). Stale revision returns conflict; encrypt before committing, swap in-memory snapshot only after write succeeds. Keep previous working revision on storage or validation failure, report a safe failure and preserve user's non-secret edits. On profile switch/restart load once before first owned external request; unreadable or undecryptable configured policy fails closed with a reachable local Settings path and deliberate removal/replacement recovery; don't treat corruption as “Not configured.” Use generation counters so stale apply acknowledgments cannot overwrite a newer edit.
- Host requests acquire immutable policy + dispatcher at admission. Use a scoped dispatcher/agent for configured proxy (e.g. explicitly declared Undici dependency matching supported Node/pinned lockfile after license review); no `process.env` or process-global dispatcher mutation in shared host/Electron. Apply bypass before selecting transport and on each followed redirect; preserve each call site's approved hosts/redirect semantics (including `redirect: 'error'`), deadlines, streaming, cancel and teardown. Rotate/dispose connection pools by policy revision only after their users finish. Translate proxy errors into fixed categories; never attach raw upstream causes, URL userinfo, headers, or response text to diagnostics.
- Scoped runtime env adapter emits HTTP_PROXY/HTTPS_PROXY/NO_PROXY with consistent lowercase counterparts where relevant (case-insensitive Windows needs one canonical key per name); explicitly remove conflicting proxy variables such as ALL_PROXY from mapped child env when configured, never from the parent. Preserve each lane's current inheritance when unset, but enforce local routing in lanes that inherit a proxy. Confirm NO_PROXY syntax in pinned SDK/CLI versions rather than trusting variable names. For mismatched suffix/IP semantics, apply rules at a Gen-owned transport/forwarding layer instead of weakening bypass. Use child-scoped Node HTTP support or explicit SDK transport where env alone is ineffective; don't globally enable flags in the host or assume Node covers vendor SDK custom agents.
- For native CLI authentication that cannot accept an explicit scoped dispatcher, first prefer a Gen-owned authenticated-local forwarding mechanism if supported by the pinned CLI and compatible with required bypass. Do not create an unauthenticated local relay granting access to corporate proxy credentials. Never send proxy credentials through renderer IPC, project shell/tool env, argv, command strings, or runtime record/log payloads. Any adapter using child-only proxy env containing credentials must prove that the designated provider child and its possible subprocesses do not pass those bytes to project tools or diagnostics. If an adapter cannot meet this with its available APIs, fail that lane explicitly and block a full-support release claim; record the compatibility finding rather than widening trust. Preserve real provider credentials and billing routes unchanged.

### Electron routing and regression boundaries

Keep `Session.setProxy({mode: 'fixed_servers', ...})` pointed at the per-profile **local pinning proxy** for the Browser partition. Do not point Chromium at the corporate proxy or put user bypass entries in Chromium's `proxyBypassRules` on that partition: either would let requests skip DNS/IP checks. The host sidecar publishes a profile-bound revision notice over its authenticated lifecycle channel; Electron main reads the sanitized policy and uses the existing private credential codec at the egress boundary (or gives the host egress ownership if the codec must not run in main). Strictly validate the bound profile, message schema and revision. No credentials in IPC payloads. Do not change defaultSession/window routing for the local UI or its OAuth callbacks. Keep local Electron UI and internal connections direct.

Inside `createBrowserProxy`, validate every destination as today, then evaluate user bypass against the original destination. Direct branch connects only to the vetted IP. Proxy branch uses the configured HTTP or TLS proxy and a tunnel to the vetted IP and port; never let the upstream resolve the original name again. Retain original origin Host and, for HTTPS, end-to-end Browser TLS/SNI to the origin. Proxy auth travels only on an upstream proxy hop, never becomes an origin header. Bracket IPv6 in tunnel authorities. Reuse request-size, timeout, header, TLS, permission and shutdown controls. Do not trust a redirect or broaden the Browser to intranet/private/loopback just because a proxy is configured. Fail without direct retry when the proxy refuses the tunnel (some proxies deny IP-literal CONNECT or CONNECT to port 80); document the limitation and verify both HTTP and HTTPS before declaring supported. A credential-bearing HTTP proxy URL does not encrypt the client–proxy hop; prefer HTTPS where supported and make that warning visible when entering credentials for HTTP.

Apply before the first Browser navigation after load/startup; keep the session isolation and existing readiness guard. On revision, make the local proxy consume the new immutable routing policy for newly started work, and discard reusable Browser connections to the old revision at a safe reload/navigation boundary using Electron's `closeAllConnections()`. A stale socket must not supply a new explicit navigation; schedule/await the cutover before loading the new page. If applying fails, retain local protection, block proxied external traffic with a safe error and allow retry/removal. Preserve the last successful direct behavior when the setting is unset; never let a failed configured path imply direct.

### Visual design and animation

- Add a searchable `network-proxy` card under the existing Accounts/Local runtime rows (keywords: proxy, corporate, networking, HTTPS_PROXY, NO_PROXY, bypass). Match existing section typography, using `--surface`, `--border`, `--text`, `--muted`, `--control-radius`, and existing button/focus classes. Card top: **Network proxy**, short profile-wide scope sentence, text status next to a small icon. Status is never color-only. Use a restrained divider, then stacked labeled fields, helper text below fields, and concise permanent “Local connections always bypass the proxy” note. Body gaps 8–12px; align actions to the trailing edge with Save primary, Remove proxy secondary/destructive, and in-place Remove/Cancel confirmation. At narrow settings widths stack/wrap actions and make fields full width; no new modal, scrolling region, sidebar, or layout jump.
- Field 1 shows only the sanitized saved endpoint outside editing; **Change proxy URL** enters a blank masked input (placeholder `https://proxy.example:8443`, no credential example). Field 2 shows comma-separated bypass with example `.example.org, build.example.net:443`. Helper copy names the Browser's public-only scope and points out the external sign-in browser still uses its own settings when applicable. Derive host-only context for web mode; don't make the usability of host Settings depend on Electron.
- States: loading (stable footprint and disabled actions), Not configured, unsaved (Save enabled only for valid dirty draft), Saving… (one request, do not move focus), Saved/Configured, Browser apply pending (“Reload Browser to use this proxy” when applicable), invalid (linked inline field message, focus first invalid field on submit), conflict (Refresh and retry, keep non-secret draft), storage unavailable (clear inline explanation, no plaintext save), network/auth/TLS error (short non-secret hint) and removal confirmation. Clear secret edit text on successful save, close, cancel, or unsuccessful submission; prompt to re-enter on retry if needed. Use one polite live status region for progress/success and an alert for submission failures; use real labels, visible keyboard focus, tab order and explicit action names.
- Only status-layer opacity and ordinary hover/focus color animate: `--ui-motion-hover` (~120ms) with `--ui-ease-move`. Keep the status slot at a stable minimum height, no bounce/slide or animated height; no delayed visibility of errors. Respect the app's reduced-motion preference and `prefers-reduced-motion`; use an immediate state change, static progress label, no spinner dependency. Verify light/dark, default and reduced-motion, and keyboard interaction at narrow and normal widths.
