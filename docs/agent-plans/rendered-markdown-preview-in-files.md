## OBJECTIVE

People opening a README, runbook or design note in project Files currently see raw Markdown in the same `<pre>` used for all text. They must read markup or leave Gen to see the document as intended. Open a readable, rendered view by default, keep exact source one action away, and retain reliable source-line navigation from Project Search. Success: the same authorized text read powers both modes; local references stay in the active worktree; external links behave like reply links and are never fetched during rendering.

Mermaid fences render as ordinary code on this baseline; if a separately approved Mermaid change lands, inherit only its safe shared renderer behavior, without requiring that work or adding diagram code here. Local links may open other readable file types through the existing Files viewer, not the OS or Browser pane.

## DESIGN

### Selection and view state

- After an eligible read and absent a forced Source intent, show Preview. Keep the selected path plus opening reason (normal, search match, local link) and effective choice together in the reader. On a different normal file selection, reset to its default and scroll the content region to top; clicking the same file or refreshing retains the manual choice. Path-only search behaves as a normal open; a text hit always requests Source and refreshes the read if the selected path did not change. Never let a late read reset the current mode, move focus or scroll another file.
- On Preview → Source or vice versa, keep focus on the pressed control, bring the newly shown body to the top, and mount only the current body. Preserve a valid match in reader state; a subsequent Source visit may scroll back to it, but only after the Source DOM commits and checksum still agrees. Never highlight stale/invalid lines; show the existing status over current Source instead. Scope scrolling to the preview region. On explicit navigation to another file from a local link, reuse Files' preview-heading/region focus behavior; keep the folder/tree context and the existing retry flow. Same-file anchor links scroll and focus the heading inside the preview region, never change the application URL, project or thread.
- Keep the host text limit (1 MiB), and add a 256 KiB UTF-8 Preview budget; for successfully read larger Markdown show Source plus “Too large to render. Showing source.” Do not parse it or enqueue images. Existing errors above the host limit and empty/binary placeholders are unchanged. Reuse one accepted text payload; switching modes makes no text read. Memoize block results per text and stable renderer options; do not enable sentence reveal or initial reveal for Files.

### Visual design and motion

- Keep the current filename header, ellipsis and checksum. Add an optional header action in `FilesView`, supplied only by eligible project Markdown, with **Source** then **Preview**, default Preview pressed. Use small text-only native buttons in a labelled “Markdown view” group, with `aria-pressed`, tab stops in visual order, Enter/Space activation, a visible focus ring and pressed weight/border/fill (not color alone). Use existing theme surface, text, muted, border, focus and selection tokens; reserve room for the control and wrap below the filename when needed instead of clipping. Do not show both controls for empty, binary, over-budget or non-Markdown files.
- Use the Files surface, existing inset and body typography; inside the scroll region place an article aligned left with a maximum prose width of 72ch. Use the shared semantic heading scale, list spacing, link treatment and table styles; images scale to article width without upscaling. Keep long code and tables horizontally scrollable *inside* their blocks, and raw Source's existing monospace horizontal scroll. Place code copy on a reserved top row in the Files code block, so it never floats over text and is keyboard-visible.
- Apply a 120 ms opacity-only entrance (0.92 → 1) to the newly selected Preview/Source body on explicit mode switches; never animate panel dimensions, scroll, content during loading, or sentence-by-sentence. Use existing motion easing and remove the transition/animation entirely under `prefers-reduced-motion: reduce`. No animation, focus change, or scroll reset on image arrival or ordinary refresh. Show concise status text for missing heading/unsupported file and inline alt/fallback text for image failure; don't expose native absolute paths.

### Renderer and navigation

- Add an opt-in Files rendering policy to `Markdown` with link/image render callbacks and a heading ID allocator. With no policy, preserve the current inline parser, DOM and behavior, including reply fragment links and animation. Pass Files policy to inline rendering in headings, paragraphs, lists and table cells (not fenced/inline code); handle image tokens before link tokens so a disabled image never becomes a clickable link. Generate deterministic, article-prefixed heading IDs using lower-case letters/numbers, hyphens for whitespace, punctuation stripped and document-order duplicate suffixes (`-1`, `-2`); make headings programmatically focusable and scope lookup to the active article by exact ID. Only claim this simple local heading convention, not GitHub anchor parity.
- Classify a document-authored target before creating DOM attributes. For HTTP(S) links only, preserve the reply anchor behavior (new tab target, noreferrer, no programmatic navigation); do not alter desktop link policy if the host handles or blocks it. Never fetch external images or external link previews. In Files, use native buttons styled as links for in-app actions with no browser navigation URL. Relative paths resolve from the current Markdown file's directory; split optional fragment first and percent-decode path segments once. Canonicalize dot segments while never popping above the worktree root. Reject absolute and scheme-relative targets, drive prefixes, backslashes, schemes other than admitted HTTP(S), queries on local targets, control characters, decoded separators, residual percent escapes that would allow double decoding, internal Git/guard path segments and malformed encoding. Limit the canonical path to the existing 1,024-character contract. Encode the vetted value using `URLSearchParams` with the current owner query; never join attacker-controlled input to an HTTP or native base URL.
- Same-file fragments only target the current article. For a valid relative file link, select through the existing project file read (using a synthetic `FilesEntry` built from the canonical path, with no change of project, thread or folder). For a relative .md link with a fragment, open Preview and apply the heading focus/scroll once after current target commit; if unavailable or too large, show a status and leave normal Source accessible. For a fragment on other targets, display the link label without an action. Existing read errors remain retryable; project directories are not opened through this path. A missing same-file heading leaves focus and scroll unchanged and announces the miss.

### Local image read boundary

- If the separately scoped project image preview has landed by implementation, reuse its authorized image read if it meets these constraints; do not depend on or ship that feature here. Otherwise add a small image-only sibling route, proposed `GET /api/projects/:projectId/file/image?threadId=…&path=…`, under the existing auth hooks in `workspace-routes.ts`. Keep `/file` and `/files` schemas and responses unchanged. In `ProjectTools`, share/extract the existing authorized-path check instead of creating another worktree authority. Resolve the current binding server-side, enforce the project file path restrictions and real-path containment, reject protected metadata, and read a regular file under `withPathGuard` using `readBoundFile` and the captured identity. Cover symlinks/reparse points, hard-link rejection, cross-owner requests, and resolution/open races with the existing host guard semantics; fail closed if a safe read cannot be established.
- v1 accepts static PNG and JPEG (case-insensitive extensions, verified signature and bounded header size/dimension inspection before sending; reject animated PNG, SVG, mislabeled and unsupported payloads). Stay at or below 1 MiB encoded and 4 megapixels decoded per image. Enforce fixed safe media types and `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, and a restrictive sandbox content policy; no absolute paths in errors or headers. Follow the existing host error conventions, not a file URL or route that serves arbitrary bytes as HTML.
- The client requests only approved relative images via same-origin authenticated fetch, with no redirect follow; use a Blob URL created from the accepted image response only (never use a document-supplied URL for `src`). Use up to eight distinct local images per document and two in-flight requests; share duplicate paths within the active Preview. Block over-limit references without traffic. Render `<img alt>` (preserve intentional empty alt on success) and a concise in-document fallback on failed/blocked/unsupported/excess images. Revoke Blob URLs and abort or discard queued/in-flight reads on owner, selected path, revision or view change/unmount. Source and denied references never start image reads. Keep image bytes ephemeral; no logs, storage or cross-document cache. Ordinary refresh can retry failed local images for the current selection once the accepted file response returns.
- No data migration, change to grants, installation dependency or persisted preference. If rollback is needed, revert the feature code and its image route together (or only its consumer if the route is shared). Existing text reads, settings and data remain usable.
