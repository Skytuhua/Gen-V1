# Highlight changed words and characters inside diffs

## META

- **Repository:** [skytuhua-org/Gen-V1](https://github.com/skytuhua-org/Gen-V1) · **Plan revision:** r1 (2026-11-21) · **Size:** medium.
- **Verified baseline:** [main at 8fa907f378127bcfc23d71b55c53625ffc43e8da](https://github.com/skytuhua-org/Gen-V1/commit/8fa907f378127bcfc23d71b55c53625ffc43e8da).

- **Provenance:** current Gen V1 renderers, preferences and tests; external demand for precise edits in long lines, bounded computation and symmetric removal highlighting. See [References](#references).

## OBJECTIVE

A reviewer should see exactly what changed in a long code or prose line without manually comparing the entire Before and After lines. Add a second visual layer to existing diffs: keep the current line/side context and mark just the changed words, with character precision within an edited word. Show deletions and insertions with equal prominence. For example, in `const timeoutMs = 1500;` → `const timeoutMs = 1800;`, mark only `5` before and `8` after; do not mark the rest of the number or the line. Review and restore behavior must stay unchanged.

Select a file in a Software Development ChangeSet to see the same emphasis in its existing numbered unified view. Changing the existing whitespace or color preference updates the view without a reload or selection reset.

**Not in v1.** No live Current Git patch or pull request reviewer retrofit, generated catalog `Diff` renderer redesign (its existing snapshot projection into Recorded is in scope), move detection, syntax highlighting, full-patch expander redesign, new keyboard bindings, edit/stage/apply/restore authority, telemetry, backend changes or third-party dependency. ## DESIGN

**Data flow.** Existing authorized source text → pure local comparison → sparse ranges keyed by source line and side → escaped, noninteractive inline spans. Proposed shared module `apps/web/src/intraline-diff.ts` takes raw snapshot pairs or unified text, with `hideWhitespace` and a caller-supplied display boundary if appropriate. Return original line indexes and sorted, disjoint half-open UTF-16 ranges (grapheme-aligned), and the optional retained indexes for snapshots in Hide whitespace mode. A unified range starts after the prefix and adapters translate it back if they render the prefix inline. Adapters still own headings, line text, numbering and controls. Never regenerate a patch from the presentation model. A missing annotation is not an error.

**Alignment and pairing.**

1. For snapshots, align equal lines with bounded longest common subsequence (LCS), preferring the earliest old-line match, then earliest new-line match on ties. Use raw equality normally; with Hide whitespace, compare after stripping JS whitespace as the existing snapshot preference does. Keep exact unmodified source strings and original ordering in each column. Treat the text between anchors as a replacement region; with Hide whitespace on, filter the equal anchors, retaining unmatched content on its original side. If the snapshot-level capacity is exceeded, reuse the existing positional whitespace filter and show no marks. Preserve blank/empty display conventions and no synthetic padding rows.
2. For unified input, only annotate inside complete ordinary `@@` hunks, using declared old/new counts and a single leading row marker; delimit edits at context, hunk or file boundaries. Recognize no-final-newline markers as metadata, not evidence of an insertion/removal or a new region. Validate counts and discard annotation for a malformed/truncated hunk. Never annotate headers, binary/combined diffs, or across files. In a valid hunk, a payload starting with literal `++ ` or `-- ` after its marker is content, not a file header. For ChangeSet, exclude any pair with either member outside the first 600 displayed rows. For History with `diffTruncated` already set, skip its entire patch's enrichment.
3. Inside each region, compare only eligible removed/added rows in source order, ignoring blank or over-cap candidates. Score by the larger of: Sørensen–Dice overlap of non-whitespace tokens (multiset intersection × 2 ÷ combined token count), or shared nonoverlapping grapheme prefix plus suffix (× 2 ÷ combined grapheme count, whitespace ignored for scoring). Require a score of at least 0.50 and a unique best above threshold for both sides; discard pairs involved in a crossing. Reserve whitespace-equivalent pairs when Hide whitespace is on so they cannot be attached to another line, but give them no marks. On a tie or unrelated replacement, keep line-level styling rather than suggest a misleading pairing. Whole-line additions/deletions have no token spans.
4. For an accepted pair, LCS word tokens using `Intl.Segmenter` for word/grapheme boundaries. Use maximal whitespace runs and individual punctuation/symbol graphemes outside word-like segments; case matters, without Unicode normalization. For a one-token-to-one-token replacement after word alignment, refine with grapheme LCS; otherwise mark the unmatched token runs. Prefer earliest matches as for line alignment. With Hide whitespace on, omit whitespace tokens from alignment, do not emit whitespace ranges, and do not bridge or remove original whitespace in the visible text. With it off, theme the width of actual whitespace changes without inserting glyphs. If Segmenter is absent or a budget would split a cluster, skip the affected annotation rather than split one.

**Fixed budgets and fallback.** Enrich at most 16 expanded files per multi-file Recorded or History view, in display order; collapse/expand can change eligibility, but no hidden per-file annotation. Use the existing pane `active` and source-tab visibility, plus native disclosure state, to gate enrichment without unmounting patch content. A comparison is eligible only up to 40,000 UTF-16 units across its inputs (including delimiters) and 600 lines total across those inputs; cap each line at 512 UTF-16 units before tokenization and each side of an edit region at 16 candidate rows before scoring. Share a 250,000 dynamic-programming-cell budget per comparison across line, token and grapheme alignment, and at most 160 diff span runs per side across a comparison (skip the whole next pair if it would exceed the cap). Check dimensions before allocation; over-budget work returns unannotated text or skips the affected region/pair, never a half-pair. Large raw rendering keeps existing behavior; no new truncation, prompts or retries. Memoize on source value, comparison eligibility and whitespace preference; palette changes are CSS only. Avoid a global text cache, worker or debounce. A source or preference change uses the new input immediately with no stale spans.

**Visual and motion specification.** Keep current monospace baseline, leading, gutters and scrolling. Mark changed runs with a stronger fill (start with a 24% mix of the semantic tint over the existing row and tune only for contrast), 2px corner radius, no horizontal padding, and a one-pixel decoration: dashed underline on removed, solid underline on added. Red/green maps removal to danger and addition to success; blue/orange maps removal to orange and addition to blue. Use the existing text foreground or an equivalent theme token proven to reach at least 4.5:1 over the marked fill; if not, reduce the fill or change the foreground, keeping the underline distinct. App high contrast keeps the decoration and makes it 2px. In OS forced colors, let the OS choose the colors (use CanvasText for the decoration if needed); decoration and Before/After or existing +/- and legend labels identify sides independently of color. Inline spans have no ARIA label, tooltip, tab stop or live region; keep existing screen-reader order and do not repeat text. Select/copy must include the same code and line breaks as before in the same view (except intentionally hidden snapshot rows). The highlight itself appears immediately: no fade, stagger, translation or other token animation on file selection, open, palette change or snapshot refresh. Keep existing surrounding transitions, including Reduced/Off behavior.

**Authority, compatibility and rollback.** Use text nodes only; do not evaluate diff contents, inject HTML, mutate the snapshot or touch staging/approval/restore paths. Preserve `(empty)`, no changes, binary, truncation, retry and permission states. Settings row descriptions explain the distinction, e.g. “In recorded comparisons, hide unchanged and whitespace-only lines. In unified patches, hide whitespace emphasis without changing the patch text.” Color copy: “Colors for additions and removals in recorded, checkpoint, and selected change diffs.” No migration; to roll back, revert renderer and copy changes together and restore the prior presentation without changing stored preferences or data.
