## OBJECTIVE

In a long conversation, text search is useful only if the reader remembers the wording. Let a reader mark a particular prompt or reply now, and use an in-thread **Bookmarks** list later to land on that exact message, even after the app has restarted or the message has moved outside the loaded history. This is a reading aid, not a new content collection. Success means the correct row, not a similar excerpt, is visible and focused; bookmarks remain private to this local app profile and scoped to the original thread.

## REQUIREMENTS

| ID | Required behavior |
| --- | --- |
| R1 | Explicitly bookmark or remove an individual user prompt or assistant reply. At most one bookmark per stable message ID in a thread. Persist after reload and desktop close/reopen in the same profile and host origin; do not migrate markers across threads. Never bookmark activity, artifacts, drafts, or placeholders without a canonical message ID. |
| R2 | A visible Bookmarks control belongs to the current thread. Its list is ordered newest bookmark first, with usable empty, populated, loading, unavailable, and retry states. A bookmark is removable both from the list and from its message. |
| R3 | Select a bookmark to move to the exact row. Work for mounted, locally windowed, and server-only history, including a target beyond the scoped reader's normal load-earlier cap. Use current authorized history and maintain bounded reads and one transcript per pane. |
| R4 | If a message was removed or is no longer an eligible message, show an unavailable item with a way to remove it. Never land on an adjacent message, substitute text, or erase a bookmark on a transient failure or because a page did not contain it. |
| R5 | Do not read on behalf of a hidden, changed, or unauthorized owner. An in-flight response may not update another pane, selection, or owner generation. Keep existing archive/side/delegation policies; local state cannot authorize a read. |
| R6 | Stay keyboard- and screen-reader-operable, light/dark compatible, narrow-pane/zoom safe, and respect reduced motion. Do not disrupt composer drafts, find highlights, normal history anchoring, active follow, or thread pins. |
| R7 | No transcript/cache copy, durable excerpt, public link, export/import, share or sync, model context, runtime command, cross-thread inbox, tags, folders, notes, automatic bookmarks, or minimap markers in v1. No new dependency or database schema migration. |

The agreed scope is manual, per-thread, local bookmarks with history-backed navigation and the exclusions above. The following layout, interaction, and contracts are the implementation decisions for this plan. Codex's minimap placement and Slack's account-wide collection are inspirations, not features to copy.

## DESIGN

### Local record and ownership

- Use one versioned journal key per canonical local thread: `message-bookmarks:v1:` followed by JSON encoding of the thread ID, inside the existing browser-profile/host-origin journal. Do not use selected navigation IDs, array indexes, raw DOM selectors, user text, model/provider choice, run ID, or ephemeral scope tokens as durable identity. Always resolve the record through an admitted thread view; do not list across keys. Keep a separate runtime fence based on active pane, canonical owner/binding generation, and request ID. A new run on the same thread does not discard bookmarks.
- Suggested strict record: `{version:1, items:[{messageId, role, savedAt}]}`. Role must be user or assistant, `savedAt` is a local integer UTC epoch millisecond; order descending with message ID as deterministic tie-breaker. These are display hints, not authority; server rechecks the actual role and membership when seeking. No title, prompt/reply body, HTML, snippet, cursor, runtime or credential data. Bound each record to 100 bookmarks; do not evict silently. At 100, allow remove and report “This thread has 100 bookmarks. Remove one to save another.” Use the existing message-ID limits where applicable.
- Use `journalReadRecord`, `journalCompareAndSwap`, and key subscription; apply idempotent explicit add/remove operations, not a blind inversion during CAS retry. Re-read and reapply on conflict, at most three attempts; never overwrite unread or malformed/unsupported records. Commit before showing success. Storage unavailable/corrupt: show an inline error, don't claim the save succeeded, leave existing durable state intact, offer retry for transient failures. Keep UI usable for ordinary conversation use even if bookmarks fail.
- List metadata is local-only, including when a matching message was deleted. Do not automatically prune on browser startup or thread switch; a target confirmed missing is marked unavailable for that open list session and can be removed explicitly. On a later activation it may be checked again. Exports, imports, conversation fork/clone, paired clients and model/context paths do not consume bookmark records. Rollback removes the UI/read extensions; records are inert and versioned, and the canonical transcript is unchanged.

### Read and navigation

1. Every activation captures the owning thread and current generation, cancels any previous seek for the pane, and checks active admission. If the exact eligible row is already mounted, commit the jump without a fetch. If present only in the current verified pane's in-memory transcript, expand/reposition its existing render window first. Never jump via a document-wide selector. For a mounted row, compare `dataset.messageId` on elements in the active transcript/owner.
2. For server-only targets, extend each existing authenticated history path with a proposed optional `anchorId`. It is mutually exclusive with `beforeId` (ordinary) or `cursor` (scoped); omitting it preserves the existing contract. A seek returns a bounded **inclusive** history page ending at the exact matching user/assistant row, in existing chronological order, with ordinary earlier-page continuation (legacy `truncated`; scoped signed `nextCursor`). Use at most 30 rows for a seek, with ordinary endpoint limits unchanged. Validate IDs, duplicate parameters and limits before lookup. Use a two-step indexed lookup of row position by thread plus ID, then bounded reads at or before that row; no text search, “page until found,” or full transcript materialization. Scoped history must use the same `read()` and `scoped()` admission, projection/slicing and sequence envelope; legacy reads must retain their outer authentication and thread admission. No new authority path or public route.
3. Distinguish missing from inability to read. After admission succeeds, an absent or ineligible anchor in that thread returns the existing page shape with no messages and no continuation (`truncated: 0` or `nextCursor: null`). Cross-thread IDs are indistinguishable from a nonexistent ID after admission. The client validates the response, including that a nonempty seek page ends in the exact eligible target and belongs to the current thread/scope; anything else is a read error, not a successful jump or proof of removal. Missing/revoked owner, bad scope, wrong sequence, network and server errors remain existing errors. Do not expose SQLite positions, unsupported rows, or foreign-owner existence.
4. On validated success replace the pane's **active transcript window** for a remote seek; don't append a disconnected old page beside the current tail or create a second transcript store. Keep only the anchor ID and scroll bookkeeping for return; use the existing history owner and evict/replace stale history data, not a bookmark cache. Show **Viewing older messages** and **Return to latest** above this window. Continue older paging from the window's first row using the existing continuation; do not accidentally page backwards from the live snapshot head. Return to latest uses the normal authoritative tail path and restores existing follow behavior. On failure leave the current window/position intact unless admission itself was revoked, when existing invalidation clears it.
5. In the scoped reader, treat seek as a new transcript read fence, share existing page/content bounds, reset the window's page budget and commit only a current response. If a polling update changes history while anchored, revalidate the active anchor through the same admitted history and keep reading position on success; coalesce polls while a seek is in flight. If the anchor disappears, report unavailable and return to admitted latest rather than leaving stale text. For App/canvas, use the existing owner lifecycle and snapshot/journal observation; keep live-tail flags off in anchored mode, and on authoritative changes that could invalidate the anchored rows, re-read the active anchor under the current owner, not every bookmark. For either owner, expire on changed thread, hide/hold, unmount, archive/revocation or navigation generation change; ignore late results even if abort cannot stop the response. Resync may reacquire the currently selected context and retry once only if the operator's selection and request are still current. Ordinary errors allow explicit retry and never remove the marker. No seek or transcript prefetch on opening the list.
6. After the row renders, the pane turns follow off, scrolls **its own** viewport to the exact row (respect sticky insets), focuses the row with `preventScroll`, then records the new reading anchor. Avoid restoration effects overwriting that anchor or sending focus to body. No focus steal on background updates. If the target cannot mount after the validated response, treat that as a navigation error with retry. Cancel pending focus and any highlight on hide, selection change or a superseding seek. The list's Escape/Close action returns focus to its trigger without moving the transcript; successful navigation focuses the message instead.

### Visual and motion specification

- Show a bookmark-outline icon plus **Bookmarks** next to the thread's existing header/find controls; on narrow panes keep the icon and accessible name. No control on new/unowned, hidden/held or unsupported views. Use native buttons and existing UI-shell action styles, theme background/text/border/focus tokens and the existing bookmark icon where available. Each eligible row has a separate 32 px minimum bookmark button at its top trailing edge, with space reserved so content never shifts on hover/save. Use outline vs filled icon, a visible focus ring, and `aria-pressed` on a stable **Bookmark message** button; show the current “Bookmark message”/“Remove bookmark” action in the tooltip. Do not require hover or right-click to discover or operate it.
- The trigger toggles a named, non-modal disclosure (`aria-expanded`, `aria-controls`) directly below the header and outside the transcript. Align to the trailing edge on wide layouts, maximum width 320 px; in a narrow pane take the available width. Use a thin theme border, 8 px radius, 8 px internal padding, and 4 px between rows. Cap panel height at the smaller of 240 px and one third of available pane height, with its own vertical scroll and no horizontal overflow; keep composer and transcript reachable. The header says **Bookmarks** with a Close button; list rows use a primary jump button and a distinct trailing **Remove bookmark** button (no nested buttons). Label entries “You” / “Assistant” and show the local saved date/time; use the bookmark role/time for accessible labels, add an ordinal if identical labels need disambiguation. No excerpt even for mounted messages. Keep usable focus after removal: next row, previous row, or list trigger if empty.
- Empty: “No bookmarked messages yet.” Loading: “Opening message…” with Cancel. Missing: “Message no longer available” with Remove; avoid an inert unlabeled action. Transient error: “Couldn’t open this message” and Retry; unavailable owner: “Conversation unavailable” without a false “removed” verdict. Announce saves/removals, seek loading and outcome in a small polite live region; use existing error treatment for persistent failures. Render status changes without auto-shifting focus; no modal or focus trap.
- On open, paint layout at final geometry, then fade the panel content in from opacity .85 over 120 ms ease-out; no exit animation or sliding layout. Change the icon fill over 120 ms without scaling or motion. Jump instantly to avoid long-distance scrolling; pulse the focused row's theme-accent outline once (160 ms ease-out appearance, then 600 ms fade), without changing layout or overriding the keyboard focus indicator. Under `prefers-reduced-motion: reduce`, disable all three transitions and show a static accent outline for the same interval; scrolling and focus are immediate in both modes. Distinguish bookmark, missing and focus states without relying on color or animation.
