## OBJECTIVE

Let someone listen to a completed reply without selecting, copying, or asking the agent to repeat it. From the same row as Copy, they can start, pause, resume, stop, and replay an existing answer. Success means Windows desktop reads the answer's prose at the selected speed with an available local voice, while the original conversation remains available and unchanged.

## REQUIREMENTS

- **R1 — Eligible replies.** Offer the action on visible, settled assistant prose, including older replies after loading history. Cover the main / embedded conversation, retained canvas, side chat, and delegated transcript. Never speak a user row, grouped work activity, tool output, reasoning, artifact, source details, or current streaming reply. A reply from the active run waits for that run to settle; older replies remain usable. If a settled run was stopped or failed, its visible persisted prose is eligible, not its error or activity row.
- **R2 — Playback.** Click the speaker to read; Pause and Resume keep the current position; Stop clears it; the speaker can start again from the beginning. Only one reply in the renderer may be active, even between split panes. Starting another reply, switching away from the owner conversation, hiding or holding the owner pane, removing/replacing the row, or closing/reloading the document stops playback. Never resume or start automatically. Keep playback state out of thread data and do not start a model request.
- **R3 — Speech input.** Use a snapshot of the assistant answer's Markdown at Play. Retain readable prose and link labels; skip fenced code, link destinations, non-prose markup and control labels. Do not modify the rendered reply or Clipboard behavior. Long replies read in order in bounded utterances without requiring repeated clicks.
- **R4 — Voice and rate.** Surface searchable `Read-aloud voice` and `Read-aloud speed` under Settings → Chat. Use renderer `speechSynthesis` and only voices advertised as local. Default to `System default (local)` and `1×`. Offer `0.75×`, `1×`, `1.25×`, `1.5×`, and `2×`; persist choices on this device profile only, and apply them on the next Play, not mid-reply. Missing selected voice falls back to the local default without erasing the stored choice. If no local voice is usable, do not send the answer to an implicit or remote voice. Explain how to recover and keep Copy available.
- **R5 — UX and accessibility.** Match existing icon controls and shell tokens. Start is visible without hover; keyboard, touch and screen-reader users get equivalent controls. Distinguish starting, speaking, paused, and unavailable states without color or motion alone. Reduced/off motion uses a static indicator. Errors are actionable and do not steal focus or expose reply content.
- **Compatibility, exclusions and privacy.** Release target is the installed Windows x64 Electron desktop app. Browser builds may expose the same UI when a local engine is available and must degrade safely otherwise. One-at-a-time playback is scoped to one renderer/document, including its embedded panes; coordination across separate native windows or browser tabs is out of scope. No mobile/background playback, voice mode, microphone, new shortcut, cloud voice, audio files, model call, playback telemetry, host API/IPC, preference sync or new dependency. Gen never requests a network TTS service; choose a local voice explicitly and verify the installed path with networking disabled.

## DESIGN

**Text boundary.** Add a pure Markdown-to-speech helper. Normalize CRLF, skip backtick and tilde fences (same-character closing marker at least as long, including when the fence is unclosed), strip comments and tag syntax without interpreting HTML, and drop inline images and bare URL destinations. Read inline-code words without delimiters, heading titles, list items without syntax, link labels without URLs, and table cells in display order without delimiter lines. Keep punctuation that carries natural pauses; preserve readable paragraph/list separation and meaningful Unicode. Detected malformed markup must not throw; retain readable prose from malformed tables, but never read fenced code or comments. For example, `## Summary` then `- Use **Settings** and [Help](https://example.com)` followed by fenced TypeScript should yield `Summary` and `Use Settings and Help`, with no URL or code. Code-only or otherwise empty output cannot start. Never extract DOM text from a row: that would include hidden labels, copy actions, source annotations or content from asynchronously revealed children. Avoid scanning on live updates; for eligible settled rows reuse the same text grammar for an actionable-prose check with early exit and cache by content. Normalize and chunk only the selected row on Play.

**Utterance and voice contracts.** Segment the normalized text at paragraph/sentence boundaries where practical (up to 240 UTF-16 code units per chunk); split at whitespace where possible, otherwise at a Unicode character boundary, with no dropped characters or broken surrogate pairs. The cap bounds each request to mitigate long-utterance stalls; it is an app choice, not a browser guarantee. Enqueue at most one utterance and retain it strongly until it settles. Resolve voices from `getVoices()` immediately and again on `voiceschanged` and on explicit Play; loading is not a permanent unsupported state. Keep only `localService === true`. Resolve by `voiceURI`; for automatic or missing selection choose a local `default` voice, otherwise a stable first local voice (sort by name, language then URI). Set the actual voice, its language when present, and rate on every utterance. Do not call `speak()` if either API is missing or no explicit local voice resolves. On a locale mismatch do not infer or transmit the reply language; use the chosen voice's language. Voice list order and inventory vary by device, profile, installed packs and Chromium build.

**Controller.** Proposed files: `read-aloud-text.ts`, `read-aloud-playback.ts`, `read-aloud-preferences.ts`, `ReadAloudButton.tsx`, `MessageActions.tsx`, and `read-aloud.css` under `apps/web/src`. Use one lazily instantiated, subscribable controller per renderer Window, shared by embedded owners, not one engine per row and not one module-global server instance. Keep only owner token (surface instance, thread ID/epoch, message ID), generation, selected voice/rate for the run, chunks/index, current utterance and phase in memory. Rows subscribe to their own state; use the same transport for every surface. Transition `idle → starting → speaking ↔ paused → idle`; `starting` allows Stop; natural end of the final chunk returns to idle, and the next Play starts at zero. Pause/Resume use native `pause()`/`resume()`; if a chunk ends during Pause, defer starting the next until Resume. Do not claim a percentage or seek position from `boundary` events; they are not required for progression.

**Cancel and recover.** Before Stop, replacement by another owner, cleanup or error, invalidate the generation, clear timers/current handlers and call `cancel()` only for owned speech. A stale row can stop only its own generation. If the owned pause latch remains set after cancel, clear it before any next utterance so the next Play is audible. Ignore late callbacks for replaced or ended chunks. Start within the user click; defer later chunks from the current generation only, with cancellation checked at dispatch. A 5-second no-`start` timeout returns to idle with a retry message. Add a generous rate-adjusted no-`end` deadline per chunk (at least 60 seconds, exclude paused time), never an automatic retry; clear deadlines on Stop and unmount. Synchronous exceptions, engine `error`, or voice disappearance end the session, clear the visual state, and show `Couldn't read this reply aloud. Try again or choose another local voice.` App-triggered interruption is silent. Missing APIs or an empty local list produces `No local speech voice is available. Check Windows speech settings and try again.` A Play retry rechecks inventory; settings can recover from the same event. No reply text, chunks, OS error payload or installed voice inventory enters diagnostics or logs.

**Surface lifecycle.** Wire eligibility once from the shared owner rules. If owner status is working but no reliable current run ID is available, conservatively withhold until the state settles rather than guessing from the newest row. Do not confuse `AssistantProse` visual reveal with host completion. On each surface, use its existing active / hidden / held / open / selected-owner signals, not window blur (the listener can use another app). Stop on owner/thread/epoch change, on replacement of the active row's content, and on row/surface unmount; register `pagehide` for document navigation. Hidden-but-mounted history must not leave speech alive. A click in another pane goes through the same controller and cancels the prior active reply before starting. Separate native renderers are independent; if a user moves an active conversation into a native window, the old held/hidden surface stops, and the destination does not auto-resume.

**Settings data.** Store `{ voiceURI: string | null, rate: 0.75 | 1 | 1.25 | 1.5 | 2 }` as JSON in versioned renderer storage key `harness:read-aloud:v1`. `null` means local automatic selection. Validate each field, never persist a browser voice object, default invalid data, and keep a session-only value if storage is blocked. Notify same-document subscribers directly and update other same-origin renderer settings on `storage` events. When a saved voice is missing, show an unavailable saved option (or a short status explaining the fallback); do not silently change the stored URI. Distinguish names that collide with a language suffix. On unsupported/no-voice builds keep rate editable and show unavailable voice state with helpful description; no settings writes are needed to play at defaults. Rollback is reverting the UI/client changes; the versioned local key is inert and no host migration is needed.

**Visual and keyboard contract.** On eligible assistant rows, add one compact in-flow trailing action group after prose, `4px` gap, existing `.icon-button` sizing with `14px` Lucide glyphs. Place Read aloud (`Volume2`) before Copy; keep Copy visible in that group at all times, and keep existing Copy positioning/visibility unchanged on other rows and in fenced code. In flow at narrow widths so the controls do not cover text or each other. Use muted idle foreground, existing hover/active backgrounds and focus ring; use the current selected/control accent during speech. Starting keeps the primary button focusable but uses `aria-disabled` and ignores repeat activation, with the name `Starting read aloud…` and a separate Stop button; speaking replaces the speaker glyph with `Pause` and adds `Square` for Stop; paused shows `Play` (Resume) and Stop. Keep the primary button node stable through all states; if focused Stop disappears, return focus to that primary button only for the same still-visible row. Otherwise do not take focus on natural completion or external cancellation. All buttons have `type="button"`, distinct visible tooltip and accessible name (`Read aloud`, `Pause reading`, `Resume reading`, `Stop reading`); decorative icons are hidden from AT. Use one polite, non-transcript status announcement per start/pause/stop/completion/error as needed, not per chunk/word; no repeated announcement of spoken content. When speech is unavailable, keep a muted speaker affordance focusable with an accessible description. For missing APIs mark it aria-disabled; for an available API with no current local voices, allow a click to re-enumerate before failing safely. Keep Copy available. No right-click or hover dependency.

**Animation.** Use existing `--ui-motion-hover` / `--ui-motion-status` transitions for background and color and a small three-bar decorative, non-layout-shifting indicator beside the active control. During confirmed speaking only, animate vertical scale over 1.2 seconds with 120 ms stagger; paused/starting state and app/system reduced motion are static, motion-off disables transitions too. No progress percentage, color-only indication, blinking, modal, new overlay or global player.
