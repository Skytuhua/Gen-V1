## OBJECTIVE

Switch between a few conversations without reaching for the sidebar or searching the entire thread history. A single Ctrl+Tab press/release from A opens B, and the same gesture flips straight back to A; holding Ctrl lets people preview several destinations before a single commit. Open a known visible row in one chord or jump to the next unread row without visiting read threads. Success means each shortcut selects at most one valid destination and never moves the composer draft, stops a run, mutates a read flag or selects anything while the switcher is only previewing.

## REQUIREMENTS

The batch specifies MRU cycling of open/working/pinned threads with forward and reverse gestures, a held-Ctrl overlay with Up/Down and release to open, positional sidebar shortcuts, next unread, rebindability, and IME exclusion. Details below (ordering, exact copy, bounded history, focus and platform policy) are v1 design decisions for this implementation plan.

| ID | Requirement |
| --- | --- |
| R01 | Ctrl+Tab / Ctrl+Shift+Tab step forward/back through the active workspace's eligible MRU list with wrap. Up/Down step through the same list while held. Opening/stepping never navigates; modifier release commits the highlighted destination exactly once. |
| R02 | Ctrl+1–9 selects the Nth actual thread row in the visible conversation sidebar, in rendering order. This respects filter, search, grouping, manual order, folds and the settled cap. Hidden sidebar or missing/non-actionable slot: no selection or implicit sidebar reveal. Scroll position alone does not change numbering. |
| R03 | Alt+Shift+U walks unread threads in unfiltered sidebar order, starting after the active conversation and wrapping once. Include folded/capped rows, skip current and archived/deleted rows, and use sidebar unread semantics (not Inbox event unread). The shortcut does not clear unread; it behaves like clicking that thread. If none other is unread, show “No other unread threads.” |
| R04 | Expose forward, reverse, each of nine slots, and next unread in Settings → Keyboard Shortcuts and its Shortcut reference. Saved overrides take effect without a restart; restore defaults per new binding. Respect existing shortcut ownership, browser-reserved keys, keyboard traversal and IME. |
| R05 | Provide the centered, bounded, theme-aware switcher specified below. Immediate keyboard feedback; full names available to assistive technology; visible focus; correct cancellation/focus restoration; no spatial motion in Reduced and no animation in Off. |
| R06 | Every commit uses existing sidebar selection and journal/placement/ownership machinery. No stale-target opens, parallel commits, data mutation during preview, new privileged commands or cross-window keyboard listeners. Existing drawers, pending drafts, in-flight runs, split-pane and detached-thread ownership survive. |

**In scope:** The main conversation workspace on Windows Electron and the browser workspace when keys reach the renderer. A thread already owned by a detached window is selected through the existing focus-owner path. No keyboard dispatcher inside a detached conversation, detached navigation, embedded pane, native child web content, or All Agents/monitor shell; those surfaces retain their present controls.

**Out of scope:** History across reloads/windows, all-history or archive search, permanent switcher UI, new unread policies / alert types, notifications changes, previous/next prompt history, capture of OS/browser-reserved keys, a new menu/command palette, shortcuts inside third-party content, backend/API changes or expanded desktop IPC. Ordinary sidebar and search remain the fallback everywhere.

## DESIGN

### Candidate data and ordering

- Use thread IDs, not DOM positions or titles, as identities. Build from the active conversation workspace's live, selectable top-level sidebar inventory (no side/delegated, archived or deleted thread, using existing eligibility where applicable). Derive a single sidebar grouping projection from existing ordering code; obtain three related views without maintaining three stores.
- **MRU:** In-memory for this mounted workspace, newest confirmed conversations first (unique, cap history at 32). Retain the current conversation and valid confirmed visits; add unvisited open split/desktop-owned rows, then working (run, working or awaiting input) and pinned rows in deterministic base sidebar order, deduplicated. “Open” means current, retained by live workspace/desktop placements, or visited in this workspace lifetime; no full-history fallback. Snapshot/stream updates and preloads cannot promote a row. Track actual active conversation changes (including mouse and normal search navigation), not speculative request IDs; promote a detached destination only after the existing focus call succeeds. When there is a current row, forward starts at the next row and reverse at the previous row; from an empty view, start at first/last respectively. Do not open if there is no alternative from current.
- **Positional:** The sidebar owns a projection of the rows it actually renders after search/status filtering and folds, plus its current settled slice. A collapsed desktop rail, closed mobile drawer or detached sidebar has no locally visible slots. Count real conversation rows only, not headings, search controls, project badges, placeholders or “Show more”; an expanded group below the scroll fold still counts. Publish the projection as data, not by querying rendered geometry or the MotionRegion's exit DOM. The first nine rows are addressable. If a row ceases to be actionable, do not silently substitute a different row during that action.
- **Unread:** Use the same grouping and project ordering on the unfiltered inventory, including all Settled rows and ignoring collapse/search and caps. Start just after the active ID (or at the first row if none), consider each row at most once and exclude the active ID even on wrap. Return only the first `presentation.unread === true` destination. Leave read/unread mutations to existing sidebar actions.

### Input, state and failure behavior

1. **Idle:** Route in the existing conversation shell key handler or a single coordinator invoked by it; match live preferences, only in a loaded main conversation workspace. For the new actions yield to `defaultPrevented`, IME (`isComposing`/229 and active composition lifecycle where needed), open dialogs/owned popovers and active menus/terminal/editor/drag scopes where a child owns keyboard input. Check scoped focus and active overlays, not role names alone. Leave existing actions and plain Tab/Shift+Tab behavior unchanged. For a direct/unread action ignore repeats; for a cycle a repeat may move one row per delivered keydown. Consume only an owned action; do not preempt browser defaults when missing a direct target. Show the no-unread status using existing feedback, once per deliberate keypress.
2. **Preview:** Snapshot eligible IDs/order at initiation and retain the physical latch that opened it (Ctrl or Meta under the existing matcher convention, or the primary non-Shift modifier on a remap; choose Control, then Meta, then Alt when multiple are held). Repeating the forward/back binding or unmodified-by-other-controls Up/Down moves within that order; releasing Shift alone does not commit. Do not reorder on refresh. If a candidate disappears, prune it and keep the current highlight by ID if possible; otherwise highlight the next remaining row in the last movement direction (wrap). Cancel if there is no longer an alternative. On owner/preset changes, blur, document hidden, Escape, composition start, preference change, modal dismissal or unmount: clear state with no selection. A later modifier-up after cancellation is ignored. Non-cycle shortcuts do not run through the open switcher.
3. **Commit:** Releasing the latch, Enter, or clicking an option commits at most once; clear/invalidate preview synchronously before acting. A choice of the already active item is a no-op. Revalidate ID and ownership immediately before the existing selection and after awaiting outgoing journal preparation. Share the click path's journal protection, pane placement and detached-owner focus; where needed expose an async result from that path without altering normal click behavior. If the owner or target invalidates, the request is superseded or preparation/selection fails, leave the current conversation and drafts intact, report through existing shell feedback, and require a fresh user gesture to retry. Do not override a later pointer/keyboard focus choice with a stale callback. Keep an in-flight ref/token so rapid keyups/repeats cannot start duplicate keyboard commits.

**Settings and compatibility:** Keep one registry declaration per action, backed by `threadCycleForward`, `threadCycleBackward`, `threadSidebar1` through `threadSidebar9`, and `threadNextUnread` proposed string keys. Use the existing Settings write path and default-migration behavior. Permit modified Tab recording when delivered without intercepting plain Tab/Shift+Tab. For new rows, require at least one Ctrl/Meta/Alt modifier so plain typing is never intercepted; reject an overlapping live app chord with a readable field error and retain the old value. Check conflicts via matcher-equivalent modifier/key normalization (including Ctrl accepting Meta); allow existing context-exclusive model picker digits because the picker takes priority while open. Existing bindings retain priority if a legacy/live config collision still occurs; no unrelated recorder redesign. Describe the current chords and the hold/arrow/release interaction in the reference. Windows Electron is the default acceptance host; a browser/OS may reserve Ctrl+Tab, Ctrl+Shift+Tab or Ctrl+digits before JavaScript. Do not promise override or install global hooks. Explain in Settings/reference that users can rebind to browser-delivered chords or click the sidebar; validate one rebind in an actual browser and document the observed browser/platform combination. Follow existing platform spelling; unverified hosts are not release evidence.

### Visual and accessibility specification

Use the shared `Modal` pattern for a short-lived centered “Switch thread” dialog, not a hand-built backdrop/trap. Place inside the main shell; retain native chrome clearance. Target 400 px width, max available width minus 32 px (16 px gutter each side); cap the list at six rows or available viewport height below the header/footer, whichever is less; rows scroll independently. Use shared dialog surface, muted border/shadow and foreground/accent/radius tokens. Header: “Switch thread”. Each row has a left-aligned single-line ellipsized title, muted project label when available, and existing pin/working/unread cues only when present. Use density row minimums 32/36/44 px; keep full title and applicable status available to assistive tech. No message previews, badges made from internal IDs, or new icon-only actions. Keep an accent outline and subtle surface fill on the keyboard highlight, distinct from pointer hover and the row marked “Current”. Scroll the highlighted row into view without smooth scrolling. Footer: “↑/↓ Move · Release [modifier] to open · Esc Cancel”, with the actual latch name; do not hard-code Ctrl after rebinding.

The shared modal owns focus; focus a single labeled listbox on open with `aria-activedescendant` pointing to the highlighted option and `aria-selected` tracking that candidate. Label each option with its full title (and project when helpful); identify current independently of the highlight. Pointer click commits; backdrop/close affordance cancels. On cancel restore focus to the previous connected, still-valid element without resetting caret or scroll; otherwise use the shell's stable focus recovery, not `body`. On commit follow normal destination focus and do not steal focus back from a detached window or a later interaction. Coordinate the existing modal cleanup with selection so focus never lands on an unmounted row. Do not attach preview keys on two layers or duplicate Escape handling.

Motion starts independently of input: shared popover timing/easing (180 ms enter, 140 ms exit at normal speed), opacity with up to 4 px vertical travel for normal motion, no backdrop fade that obscures chat, no scale or row stagger. Highlight and selection update immediately even mid-animation. Use existing motion tokens/speed; Reduced removes travel with at most 80 ms opacity, Off is immediate. Interrupt cleanly if released/reopened before exit. Verify native child content stays occluded wherever the existing shell requires it; if a child owns focus, leave its keys alone.

**Data boundaries and rollback:** No new persistent data except shortcut preference strings. Do not persist MRU IDs, log keypresses/titles, read message content for shortcuts, add dependencies or expose capabilities. No DB migration. Roll back dispatcher, UI and preference defaults together; old reads already tolerate unknown stored fields. Do not remove unrelated overrides. Do not ship an unsupported native shortcut fallback silently; release hold if Windows Electron cannot deliver the defaults through the existing focused renderer.
