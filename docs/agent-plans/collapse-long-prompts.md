# Collapse long prompts in the thread

## META

- **Repository / size:** `skytuhua-org/Gen-V1` · feature · small (batch 7, item 5).
- **Revision:** 1 · 2026-11-21. **Baseline:** [main at `4ca1134ae1e4f354064457cb5664b545712da4a9`](https://github.com/skytuhua-org/Gen-V1/commit/4ca1134ae1e4f354064457cb5664b545712da4a9).

## OBJECTIVE

Pasted logs and specifications can occupy more than a viewport in a Gen thread, making it hard to follow the conversation. Default long sent user prompts to an eight-line-height preview. Make it possible to reveal the entire original rendered prompt in one action, collapse it again without scrolling to its end, find text past the preview using existing Conversation Find, and copy the original prompt without expanding.

## DESIGN

### Disclosure and threshold

1. Add a shared, user-only `UserPromptDisclosure` around the single existing `<Markdown text={message.content} />` in each App owner. The full inner Markdown stays mounted and raw content never gets sliced, normalized or duplicated. Artifacts and row-level Copy stay outside the clamp; do not add a nested Find block marker. Short prompts have no disclosure button, mask, height limit or new focus stop.
2. Use a dedicated, intrinsic-size inner content box with `display:flow-root` to contain Markdown margins, and a separate outer clip. Use `min-inline-size:0` on both and match the clip's sizing reference to the current Markdown typography: `font-size:14px; line-height:1.65`. Set the cap to `8lh` (184.8px at that reference size). Use the same cap for comparison and clipping; convert the clip's computed line height to pixels for the comparison. A prompt is eligible only when intrinsic height is **greater than** cap + 1 CSS pixel (subpixel tolerance). Measure before paint for visible rows, observe the content box for wrap, font, resize and content changes, and coalesce repeated equal measurements. Do not classify a zero-width hidden cached panel as short; defer until measurable. No raw-character cutoff: blank Markdown lines need not take up screen space, and one wrapped paragraph can be long. If the content fits after resize, show it normally and hide the control; if it overflows again, honor its last explicit or Find-driven expansion while mounted, defaulting to collapsed if never expanded.
3. State belongs to the mounted message in its thread; distinguish eligibility from `expanded`. Initial eligible state is collapsed. Manual toggle flips that row only, Find sets expanded idempotently, and Find exit or query clear does not re-collapse. No cross-thread reuse, data model field, storage, or persisted preference; disposal/remount starts collapsed. For same-row content changes remeasure but keep the disclosure choice; for identity changes reset it. If resize removes a focused toggle, move focus to the still-mounted prompt wrapper with `tabIndex={-1}` and `preventScroll`, not the document body. If remeasurement would make an already-focused Markdown descendant inert, keep that row expanded to preserve focus.

### Visual design, interaction and motion

- Keep current bubble geometry and tokens; no new theme palette. Place a single disclosure button in a top rail, before the clip. Rail uses `position:sticky; inset-block-start:0; z-index:1; display:flex; align-items:center; min-block-size:32px; margin-block-end:4px; padding-inline-end:32px` (clear the existing right-side Copy). Give it the owning bubble's opaque background: `var(--subtle)` main, `var(--selection-bg)` Canvas; verify its composited appearance in both themes. The rail's containing block spans only the prompt, with no overflow between rail and existing transcript scrollport. It follows the prompt out of view and must not overlay another row, the composer, or shell overlays. Keep it in normal keyboard order before the controlled content. Do not create an inner vertical scrollport.
- Button: `<button type="button" className="quiet …">` with **Show more** / **Show less**, a decorative 14px down/up chevron (`aria-hidden`), 6px gap, 13px text using `--text`, 32px minimum block size, and padding `4px 8px`. Use quiet-button hover, `--control-radius` fallback 6px, and `:focus-visible { outline:2px solid var(--ui-focus-ring); outline-offset:2px; }`. Button stays usable when the card is narrowed/zoomed, with no horizontal page overflow. The rail and mask are absent for short prompts; preserve existing Copy position and behavior.
- Collapsed clip: `max-block-size:8lh; overflow:clip; mask-image:linear-gradient(to bottom,#000 0,#000 calc(100% - 24px),transparent 100%)`. Use a scoped `overflow:hidden` fallback on the **clip**, not the rail or bubble. No pseudo-element intercepts clicks and no ellipsis is the only disclosure affordance. Expanded at rest: no max height, mask, or overflow clipping on the wrapper. Keep Markdown's own code/table scrollers.
- Give the persistent clip a stable DOM ID with `useId` and the toggle `aria-controls` and truthful `aria-expanded`. Use native Enter/Space activation; keep focus on the same button on both toggles. Put `inert` on the **preview content subtree only** when collapsed so neither a clipped link/table/code button nor inaccessible offscreen text takes focus or appears in the accessibility tree. On collapse the user can use the message-level Copy or expand to select or interact with Markdown. Add an `.sr-only` description associated with the collapsed button: “Preview clipped. Expand to read the full prompt.” Expand removes inert; no forced focus into Markdown and no extra live-region announcement. Do not apply inert to the rail, Copy, or the enclosing row.
- Manual toggle: animate clip block size from current measured pixels to natural height/cap in **180ms**, `cubic-bezier(0.2, 0, 0, 1)`, using a node-local cancellable animation (e.g. Web Animations). Remove fade immediately on expand and apply on collapse settle. Drop temporary inline constraints on settle; a new toggle reverses from the currently presented height. Feature-detect animation/observers and settle synchronously when unavailable, when Find reveals, or when `readMotionPolicy() !== 'full'`. In browsers without ResizeObserver, remeasure on owner-window resize and committed text changes. Cancel/settle on remeasure, motion change or teardown; stale callbacks must never reapply clipping. Prefer one transient animation per active toggle, no global polling or arbitrary timeout.
- Scroll in the existing transcript only. The rail remains in view as the long prompt is scrolled; on collapse from a formerly deep position, keep the focused/top rail in the scrollport, at most correcting the owning scroll position to put the collapsed rail just inside its upper edge. Do not scroll window or composer and do not jump to the global tail. A successful tail-follow when already following new content is separate; explicitly test a last-message case and an older detached-reader case against the actual main controller. If its spring overrides an explicit Find jump or a necessary rail correction, route the scroll through the controller or add a narrow explicit reading-intent entry point that interrupts the spring before the write and remembers the resulting position; do not change generic tail thresholds or paging logic.

### Find wiring and failure handling

1. Retain the existing DOM Range and CSS Highlight approach. Register each mounted disclosure by its content wrapper element in a module-local `WeakMap`, from a layout effect with cleanup on teardown. Give that wrapper a dedicated data marker; do not register generic inert descendants or add a second search corpus. The scanner may bypass **only** the exact registered preview wrapper's inert boundary while walking an otherwise valid, visible owner block. Walk/check ancestor gates rather than using one `closest('[inert]')` exemption that could miss an outer inert owner. Keep all other exclusions (`button`, input, labels/status, normal hidden/aria-hidden/inert ancestors, CSS invisibility). Preview clipping must not use `display:none` or `visibility:hidden` on the searchable Markdown. Do not parse raw source for Find; current rendered-text key/offset and cross-node matching behavior stay.
2. In `ConversationFind.jump`, identify any registered collapsed clip intersected by the selected Range (check start/end or intersecting registered wrappers in the owning message). Compare the matched rects against that clip's usable bottom edge (cap minus 24px fade), not against the transcript viewport; a match merely scrolled offscreen is not a reason to expand. Ignore empty rects, handle cross-node matches spanning the boundary, and treat an unmeasurable selected range in a visible collapsed clip as requiring reveal. A visible preview hit follows the existing immediate path. A clipped selected hit queues reveal only for the affected message, never all matches.
3. Split jump into request/reveal and final positioning. Module registration exposes a **non-animated** reveal request; the row updates its state and acknowledges from a layout effect after clip/mask/inert removal. Resume using the latest Range for the same stable selected key, current transcript and owner; invoke existing highlight/positioning/`onNavigate` once after the acknowledgement. Do not rely on a fixed delay or force React flush from a layout effect. Center only after layout resolves, clamp to owning scrollport, and ensure the selected rect is not behind its sticky rail. Background rescans keep selection and counts but never trigger reveal/scroll on their own (except the existing initial selection for a changed query).
4. Invalidate pending work on a newer navigation/query, active owner change, Find close, hidden owner, or teardown; guard against a disconnected row or replaced Range before scroll/highlight. If the target disappears, retain existing key-based result fallback with no stale scroll/focus write. If a user explicitly collapses a selected prompt, do not auto-reopen it on the ensuing DOM mutation; an explicit subsequent Find jump may reveal it again. Keep focus on the Find input/button throughout auto-expand.
5. No migration or feature flag. Roll back the presentation, Find opt-in, and associated tests together; no saved data or preferences need repair. Only process content already rendered in the owner's loaded transcript. No new requests, clipboard reads, telemetry or transmission of prompts; do not put real prompts in test artifacts. Avoid rescanning the transcript on every animation frame or measuring each message during every Find keystroke.
