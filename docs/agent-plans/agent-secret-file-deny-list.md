## OBJECTIVE

A developer wants the agent to work in a repository without sending local credentials or secret filenames through routine file reads, directory listings, search results, or composer references. A resource grant should not override the developer's protection rules. Protect common secret paths on fresh and existing profiles, let the developer add a private rule globally or for one project, and make an explicit denial understandable without disclosing the blocked file to tools or models.

Success: in supported project and working-copy paths, protected fixture names, bytes, previews, hashes, and derived context never appear in covered data flows after the relevant rule takes effect. An ordinary sibling remains readable, searchable, and mentionable. A project rule never weakens global policy. Human inspection of the filesystem remains available and clearly separate from sending data to the agent.

**User flows.** In Settings, edit **All local projects** or choose a connected local project. Paste one deny pattern per line, read the preview of rule semantics (not a live filesystem preview), and save. A project shows the inherited global rules read-only. To intentionally permit a previously blocked pattern, remove the matching rule at its owning scope and save; another matching rule still wins. When asking an agent to read a known blocked file, expect a generic policy denial. When searching or picking a file, the entry is absent. If a previously picked file is blocked by a later save, keep the typed prompt, mark the stale choice and let the user remove it before retrying.

**Out of scope.** No shell/terminal/process sandbox, outbound data-loss prevention, content-based scanning, deletion, retroactive cleanup of prior context/transcripts, browser or MCP policy, integration/remote or company-governed projects, Git history/diff redaction, or system-wide filesystem permissions. Existing pre-commit secret scanning and project trust stay separate. This cannot protect content already copied into a prompt, pasted, or uploaded without verifiable project origin; never imply otherwise. Do not build the independent file-mention experience or approve a confinement backend in this issue. The policy covers structured file entry points, not arbitrary execution or arbitrary agent access to local data.

## DESIGN

### Policy and authority

- Host-owned, machine-local policy in the existing local profile store. Persist a versioned global record and a versioned record per local project ID, not per branch or worktree. Use one monotonically increasing revision per scope; bind a request to the relevant pair. An absent global record resolves to the shipped defaults at revision zero; an absent project record is empty. An explicitly saved empty global list is distinct from absence. Do not write configuration to Git, read project-defined ignore/config files as policy, sync rules externally, or expose the editor API as an agent tool.
- Effective deny is the union of global and applicable project rules. If more than one authenticated origin applies, honor all applicable project rules. No allow override, precedence by ordering, one-time policy bypass, or agent-controlled flag. The host derives origin, project ID, working-copy ID, and path from existing binding/grant records, never from an unverified caller hint. Global rules apply across local projects; for a standalone covered directory grant, use its admitted root; for a standalone covered file grant, basename-only rules apply. Never treat a known project-origin file as standalone. If an expected owner or root cannot be proven, stop the covered operation instead of falling back to less protection.
- Example shipped defaults (one per line): `.env`, `.env.*`, `**/secrets/**`, `*.pem`, `*.key`, `id_rsa`, `id_ed25519`. These intentionally include `.env.example`; the editor must say so. A file type is not a content detector. Reset Defaults stages the shipped list and requires Save.
- Limited grammar: trim surrounding whitespace and ignore blank lines; literal names, `*` and `?` inside a segment; `**` only as an entire segment. Rules without separators match any complete basename under the admitted root. Rules with slashes match the full root-relative path; trailing `/**` includes its directory and descendants. `secrets/**` is root-only; `**/secrets/**` is any depth. Reject absolute/drive/UNC paths, backslashes in rules, invalid or control characters, empty segments, parent/current-directory tokens, leading negation, braces, bracket classes, and comments. If literal glob metacharacters are required, defer escape support rather than silently accepting a different grammar. Bound to 100 rules per scope and 256 UTF-8 bytes per rule; deduplicate canonical rules server-side, preserve first occurrence, and return line-numbered validation failures without echoing inputs in logs. Use bounded matching; no regex interpolation, shell invocation or filesystem glob expansion. Match dotfiles and apply the same NFC plus locale-independent case fold on all supported platforms; ambiguity is denied, never resolved to weaker policy.
- Use existing platform pathname validation and guards, including documented unsupported path/identity cases. Evaluate both normalized admitted logical path and verified canonical path after containment checks and before opening, hashing, or returning derived information. Preserve link/reparse protections; where identity is uncertain, reject rather than weaken custody. Scan/recursive listing silently prunes a denied child; direct operations get a distinct safe typed denial (proposed `FILE_POLICY_DENIED`) and the user text “This file is blocked by your agent file rules.” No denied paths, matched patterns, lengths, hashes, previews or path-specific counters in tool, model, receipt or telemetry output.
- Take a current policy snapshot before traversal. Recheck ownership and revision under existing guarded custody before any covered open and at the relevant response/publish/dispatch commit boundary. Abort and discard stale results (including allowed-looking data from an obsolete revision); do not substitute an allow result on read errors, cancellation or corrupt/unavailable policy. Existing consumed content cannot be recalled. For search, bind snapshots/cursors to revision as well as owner; invalidate model/UI caches on policy update, and do not return old pages from in-flight requests. Recheck any retained file reference or cached material before reuse; known blocked bytes must not be copied into a request, captured source, or compaction input just because a previous operation was allowed.
- Preserve all original grant, storage, process, timeout and cancellation behavior. Do not install a user-configurable bypass flag. Compatibility is lazy migration (virtual defaults on missing state); rollback of a UI issue should leave persisted policy and host denial intact. If host enforcement must be rolled back, disable affected structured operations rather than ship UI claiming protection; do not modify project-trust/confinement flags. Document local scope and prior-context limits.

### Settings and denial UI

- Put **Agent file protection** in Settings → Projects & Working Copies, indexed for “secret”, “deny”, “agent file” and “.env”. Use the existing settings section styling, neutral card/surface, lock icon plus text (not color alone), 16px inset, 8px stack gaps and existing 32/36/44px density heights. Title and one-line explanation above an existing labelled scope selector. On narrow widths stack the scope selector, editor and action row; allow pattern text to wrap without clipping. Use theme tokens and existing focus rings; no bespoke dialogs or decorative effects.
- Provide an explicitly labelled monospace multiline field, rule examples and per-line errors. Show inherited global rules in a labelled read-only list in project scope (visible only to the authenticated operator, no paths read from disk). Footer copy: “Blocks supported file tools, project search, and file references. It doesn’t sandbox terminals or remove content already shared.” Use **Save rules**, **Discard changes**, and global-only **Reset defaults**. Switch scopes with a dirty draft only after a Save/Discard/Cancel choice in the existing shared dialog. Keep the current draft and show Reload on a revision conflict; never overwrite another window silently. A failed save is not presented as applied.
- Announce saved/conflict/blocked state via shared status/alert and `aria-live`, associate errors with the field, and keep keyboard focus on the initiating control or first invalid field. Search and mention use their usual empty state without reporting blocked file counts. Mark an already staged, now denied chip “Blocked by file rules”; the chip can be removed. Keep draft text and allowed chips on a denied Send. Do not show a path in the error itself; if it was already consciously selected, replace the visible chip label on policy invalidation rather than retaining its stale path/preview.
- Motion uses existing UI-shell tokens: 140ms scope crossfade and 160ms status opacity only; no layout slide, animated focus, or stagger. A chip disappearing on policy change hides protected content immediately; animate only its redacted container on explicit removal with the existing attachment motion. Reduced motion is opacity only at most 80ms; Off is instant. Never delay enforcement, validation, announcements, or focus for animation.
