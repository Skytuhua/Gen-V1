# Hermes-style learning integration

Implement the requested procedural self-improvement loop in the existing Harness. Source authority: NousResearch/hermes-agent `c627ec84664d43e0b18b95d9d86d8963747d56c7` (MIT). Compare Codex, OpenCode, Pi, Goose and Aider from pinned primary code; no claim of universal quality parity follows from source similarity.

## Decisions

- One application-owned skill library in the existing SQLite Store, shared across sessions and all nine provider IDs. Reuse the shared host tool registry, runtime factory, account claims, HTTP/SSE, settings and native approval boundaries. No Python agent, plugin runtime, vector database, extra daemon or new dependency.
- A skill has name/description/category, Markdown instructions, bounded supporting text files, stable revisions, source/provenance, usage and active/stale/archived state. Render a standard SKILL.md document from its structured metadata. Skill bodies and files load on demand; snapshots and automatic context carry metadata only.
- Expose Hermes-shaped `skills_list`, `skill_view`, `skill_manage` tools. Management takes an atomic operations array for create, patch/rewrite, write/remove support file, delete/archive, restore and rollback. Existing versions are immutable. Stale base revisions, ambiguous patches, traversal, oversized content and obvious credentials fail closed. Supporting paths are identifiers, never filesystem authority.
- User controls include inspect/edit, enable/disable, pin/protect, archive/restore, revision history/rollback and optional approval of agent writes. Automatic writes are enabled by default as requested; approval mode stages the complete batch before activation. A user-disabled or protected skill cannot be silently re-enabled/rewritten by an agent or curator.
- Main tasks discover/load useful skills and improve them while working. Host-built per-turn metadata exposes current changes without enabling native SDK scanning of arbitrary local skill directories. Explicit `/learn` guides the main agent to distill the current workflow or supplied sources using the existing tools.
- Automatic review is actual additional model work after a successful, non-aborted settled turn, once ten foreground tool calls have accumulated since the last skill write/review. It inherits the source model/account, uses a separate owned runtime session and a bounded canonical transcript/evidence excerpt. At most one review, sixteen tool calls, 64 KiB input and a 60-second deadline. Foreground work cancels review; no restart replay and no recursive learning from review runs. Empty/no-change results are normal. Quota use is visible and can be disabled.
- Review dispatch permits only skill reads/writes and bounded past-conversation search. Require a fresh review-local read before changing an existing skill/file, plus exact base revision. No resource mutations, primary-thread messages, UI, grants, approvals, delegation, external installs or native history recovery. Read-only side/planning sessions cannot mutate the global library.
- A passive curator runs weekly only after two idle hours. Mark managed agent skills stale after fourteen unused days and recoverably archive after thirty. Respect pinned/protected/user-owned/disabled records. Seed scheduling on first startup and do not infer that old imports are unused. LLM consolidation is not enabled; deterministic curation needs no model call. Every transition remains inspectable/reversible.
- Cross-session search returns bounded existing app conversation excerpts with their thread/source IDs, explicitly untrusted and never a grant or execution receipt. Thread-local `task_memory` remains unchanged. No external memory provider or user-modeling service.

## Boundaries

This is a Harness adaptation of Hermes's procedural learning loop, not all of Hermes. Inline-shell preprocessing, automatic dependency installation, arbitrary project/external roots, marketplace imports, Honcho/user modeling, alternate memory backends, visual learning graphs and cron/chat integrations are outside this integration. Loading is text-only. Standard SKILL.md/supporting-file export is data, not execution permission. Existing generated-app and live-auth acceptance gates remain.

The existing audited native pipe-error paths must be guarded before enabling automatic native reviews. Preserve process/account ownership through startup, cancellation and disposal; report unconfirmed teardown instead of falsely declaring an account idle. No credentials from the user's Codex profile are read or modified.

## Proof

Use tests first for atomic batches, rollback, fresh reads, version conflicts, protected/disabled records, approval, support paths and budgets. Prove real Service/Store create → improve → reopen → reuse in another thread, and all nine provider IDs reaching the shared host tools with captured accounts. Use deterministic runtime fakes for review cadence, restricted tools, startup/stop races, input/tool/deadline limits, nonrecursive completion and no replay. Prove passive curator timing/protections and UI inspect/conflict/approval/archive/restore. Native package/bootstrap and live-model learning quality are separate evidence scopes; scripted writes do not establish autonomous usefulness.
