# Company Task & plan surface

Open `/company`, choose a project, then open **Task & plan**. The panel starts docked beside the manager conversation (below it on a narrow screen). **Float task panel** presents the same task body in the existing movable, resizable in-page window. **Dock task panel** returns it to the split view. Floating-window movement, height controls, minimize and reset use the existing Gen window primitive.

Closing or pressing Escape returns focus to **Task & plan**. Opening it again keeps its placement. Placement and open/closed state are saved separately per project in the existing company-local journal; a project with no saved preference inherits the current working panel's placement and open state. Manager drafts keep their existing per-project keys. Docking/floating keeps the task body mounted and does not issue a task/plan read. Reload restores a saved read as historical; it does not refresh eligibility automatically.

Only the host's exact approved-job selection can appear, and only in the matching project. Moving or reopening the surface creates no project binding, message delivery, permission, execution or approval. Send remains disabled under the current local-proposal contract. Generated-code execution remains unavailable.

In a supported native company host, **Detach task into separate window** opens a genuine native task window. The desktop and renderer both bind it to the existing company/project/WorkOrder identity, with current project reads and the unchanged full approved-ref checks. The main task body remains until the child completes recovery and announces ready, then becomes a focus affordance; the manager conversation stays usable. **Dock in main window** flushes saved state, returns to the exact validated project, and opens its docked task panel without issuing a plan read. A busy task read or failed save blocks moving/closing. Cache updates use existing journal notifications and are validated as stale historical projections. No personal desktop provider or service is mounted.

The detached renderer uses only the trusted desktop context; the immutable native URL carries a window ID, not task bindings or arbitrary destinations. A browser without the native bridge offers in-page dock/float only. Source bridge tests are distinct from personal Gen's actual Electron window verification; no physical multi-monitor or live manager readiness is inferred.

Focused source verification uses `tests/e2e/company-task-surface.playwright.config.ts`, a disposable read-only fixture with the actual company CSP, and isolated explicit output paths. It does not call the owner service or use real credentials/models. Matching native preview/build ownership remains with personal Gen.

For an isolated source view, run `pnpm exec vite --config tests/e2e/vite.config.ts --port 5510` and open `http://127.0.0.1:5510/company`. This test configuration does not proxy personal or company APIs; unavailable connection states are expected without a separately authorized host. The reviewed renderer handoff is `D:/GenCompanyTaskSurfaceVerification/20261104/web-native-fixed`; personal Gen connects that renderer to the existing trusted host in its separate native capsule. The earlier `web` directory is retained as pre-native-URL-fix output and is not the final handoff.

In native mode, view changes update only local journal/selection state and preserve the complete entry URL, including `desktopWindow`. Browser navigation retains its existing route updates. This presentation check does not alter native sender/URL custody or grant a new capability.
