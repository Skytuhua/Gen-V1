## Validation boundary

[`validateReadOutput(kind, raw, expected)`](../packages/company-contracts/communications/reads.ts)
accepts raw `Uint8Array` bytes and returns deeply frozen `Conversation`, `Message`,
`ConversationPage` or `MessagePage` data. The expected company and scope must come
from an independently permitted read context. Matching them does not authenticate
the caller or grant access.

The validator checks the 262,144-byte raw output limit, strict JSON lexical rules,
the pinned schema, every nested company/scope reference, page visibility and
conversation coherence, duplicate IDs/sequences, included reference metadata,
decoded UTF-8 field limits and each record/page digest. Digests omit only their own
top-level `digest`; nested records are checked independently. Errors use fixed
codes and do not include submitted content.

Pages retain partial/unknown coverage, null counts/cursors and explicitly
unavailable replay/snapshot metadata. Observation labels and recorded authors are
descriptive data; even a valid digest or `stored_record` label supplies no authority
or live verification.

The existing strict JSON implementation moved to an internal shared module.
[`decodeJson`](../packages/company-contracts/communications/index.ts) still enforces
the frozen 32,768-byte command boundary. Old command exports and the raw C01 bundle
retain their semantics and pins. The historical C01 source receipt remains
historical because the implementation was refactored in this new checkpoint.

## Verification scope and missing prerequisites

The new tests consume all six examples, 57 shared cases, eight raw rejection
vectors and eight generated byte/hash recipes. They include the 43,995-byte valid
page, exact 262,144/262,145-byte boundary and multibyte field limits. Extra tests
cover explicit scope binding, unknown versions, included reply metadata and deep
immutability. The frozen command tests exercise the extracted JSON implementation.
The original reports were stored under `test-results/company-reads-*`.
Those raw reports and the final `2d1ce18d...` checkpoint were later lost when a
personal Playwright run cleared that directory. The observed test outcomes and
review messages remain historical transcript evidence. See the
[custody incident](company-evidence-custody-2026-11-02.md); no replacement run or
reconstructed receipt is claimed.

The packaging owner admitted only the new runtime schema path and retained the
three existing paths; manifest/goldens stay excluded. Static asset closure does
not establish that a new installer contains or executes this consumer.

Canonical Conversation/Message storage and the current registry actor adapter
(C03), authorized snapshot/cursor/replay issuance (C07), owner gateway and tools
(C08), and communication views (C09) remain incomplete. Legacy mailbox records are
not converted into canonical records. No operational read API, persistence,
transport, credentials, model turn, employee activation or E01 cutover is added.
This checkpoint does not establish full C01 or any live acceptance.
