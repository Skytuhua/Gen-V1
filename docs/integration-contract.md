# Public integration contract

Last updated: 2026-10-31.

Shared types live in [packages/contracts/index.ts](../packages/contracts/index.ts). Paths below are relative to the project. This describes the current source contract; availability and verification are tracked separately in [acceptance.md](acceptance.md).

## Browser API
- GET /api/bootstrap -> {csrfToken,widgetOrigin}; cookie authentication, then x-harness-csrf for commands.
- GET /api/snapshot -> Snapshot.
- GET /api/models -> {models: ModelInfo[], error?: string}. Successful discovery is cached and concurrent requests share one lookup. Use ?refresh=1 or ?refresh=true for explicit refresh; other refresh values return 400. Failures remain retryable. The selected runtime independently validates its authentication context and model at task startup; an advertised/static catalog is not proof of account entitlement.
- GET /api/events?after=N -> SSE event workspace; data is WorkspaceEvent. Refresh snapshot after accepted events; ignore old sequences.
- POST /api/commands -> CommandReceipt; body HostCommand.
- GET /api/artifacts/:id/source -> current source text. Inspect a held revision from its immutable ArtifactRecord, not this latest endpoint.
- GET /api/resources/:id/content?path=<relative-file> -> granted attachment/file content, bounded to 20 MiB. Omit path for a direct file/attachment; use a URL-encoded relative path for a file below a directory grant. Resource guards apply through final I/O; this is not an arbitrary-URL proxy.
- GET /api/artifacts/:id/mount -> {url,token,mountId,revision}; currently rejects with CAPABILITY_UNAVAILABLE because generated apps remain disabled. Once accepted, the URL uses the separate loopback origin http://localhost:4318/widget/:artifactId/:revision, a short-lived one-use ticket query and mount credentials in its fragment. It carries no host credentials.

Command types / payload:
- thread.create {title?,projectName?}; thread.rename {title}; thread.archive {}.
- thread.mode {mode:"plan"|"build"}; change only while the thread has no active run. Older records default to Build. Plan mode denies operation preparation/approval at the host boundary.
- message.send {content,modelId,thinkingLevel?}; run.stop {}; run.resume {modelId?,thinkingLevel?}; run.compact {}. thinkingLevel is an advertised string or null for the runtime's explicit default; changing it during an active run is rejected. Compaction follows the selected runtime's confirmed capabilities and may be unavailable.
- settings.update {theme?,modelId?,preferences?}; preferences is a validated partial patch from [packages/contracts/preferences.ts](../packages/contracts/preferences.ts). showUsageFooter defaults to true; unsupported keys cannot change authority.
- memory.save {key,content,baseRevision}; memory.delete {key,baseRevision}. These user commands edit only the named thread's notes; the same limits and revision checks as task_memory apply.
- resource.grant {path,kind,label?,writable?}; resource.upload {name,mimeType,base64}.
- state.save {stateId,baseRevision,values,clientId,clientSequence}.
- edit.begin {stateId,fields,clientId}; edit.end {stateId,clientId}.
- action.submit {artifactId,revision,actionId,payload,clientId?,baseStateRevision?,submittedState?,dataRevisions?}.
- request.respond {requestId,revision,response}; request.withdraw {requestId,revision}.
- request.detail {requestId,revision,kind:"explain"|"examples"|"more-options",optionId?}; optionId identifies an existing option except for more-options. The decision remains pending; the accepted input is queued durably for the selected runtime. Duplicate pending detail work is reused. Terminal unanswered requests become failed/retryable, preserving the decision and draft; stopped/interrupted tasks require Resume first.
- operation.approve / operation.reject / operation.reconcile {operationId,revision}.
- artifact.expand {artifactId,expanded}; artifact.pin {artifactId,pinned}; artifact.archive {artifactId}.
- widget.checkpoint {artifactId,revision,clientId,baseStateRevision,stateSchemaVersion,values}.
Errors: {error:{code,message,details?}}. Commands use HostCommand {id,type,threadId?,payload}. Browser commands generate UUIDs; retries reuse the same ID and identical body.

## Surface conventions
SurfaceSpec is a json-render flat graph {root,elements}; each element is {type,props,children?}. The 48-component catalog supplies strict schemas and valid prop examples. It includes ChoiceList, Steps, RelationshipGraph, Status, DocumentPreview, SignaturePad, MapView, Diagnostics, ChangeSet, ApiExplorer, Pipeline, ImageCompare, WorkflowBoard, ArchitectureCanvas and TraceWaterfall; see the [catalog contract](../packages/ui-catalog/README.md) for conventions and the exported schemas for exact props/bounds. Admission checks graph size/depth, references, allowed children, unknown props, cycles and reachability. Task component families load lazily in the trusted renderer.

Artifact bindings map alias -> snapshot/live DataBinding. Resolve data into an artifact-local namespace; never interpolate executable expressions. State keys are stable bare field names under the artifact's UserStateRecord. rowsBinding/dataBinding name aliases; resourceId names a separate opaque resource grant. On composition, every component resourceId, beforeResourceId and afterResourceId must belong to the active thread; actions and bindings must exist. Numerical Progress components must bind executor-owned data.

Form and Button identify actionId in artifact.actions. Both accept payload and payloadFromState, whose entries map payload property names to saved state field names. The renderer combines the literal payload with values read at submission; mapped fields take precedence. For example, payloadFromState:{choice:"deliveryMethod"} submits the current saved deliveryMethod as choice. Form also accepts submitLabel. These submissions use the host action envelope and native broker; local choices never approve operations.

ArtifactRecord.presentation is optional for existing records. ui_present/ui_create_widget accept presentation:{width:"compact"|"standard"|"wide",frame:"card"|"canvas"}; both members are required when supplied and unknown members are rejected. New artifacts default to standard/card; updates retain their presentation when omitted. All inline width/frame variants share a visible container at the user's composer width and let chat own scrolling. Explicit expansion and workspace sizing retain the presentation metadata. Width and frame control composition, not arbitrary CSS. Updates require the existing artifactId and current baseRevision. initialState initializes new artifacts only. Expansion keeps one mounted artifact and its draft state.

ui_present accepts exactly one of spec or patches. New objects use a complete spec. Existing structured objects may use at most 200 add/remove/replace patches under /elements or /root with artifactId and the current baseRevision. Paths use JSON Pointer escaping; unsafe prototype keys, missing parents and invalid targets fail closed. The resulting complete surface is validated before publication, and edit leases still protect active user fields. Omitted title and purpose retain their existing values, as do admitted presentation, bindings and actions. The Pi TypeBox schema exposes this patch contract; small changes need not resend the complete surface.

DocumentPreview accepts a thread-owned resourceId and optional resourcePath, encoded as the content endpoint's path query. It renders actual PDF pages with local legacy PDF.js/canvas and shares field/signature state with contextual controls. SignaturePad retains legacy typed/points records and supports multiple normalized strokes plus bounded generated/uploaded PNG resources. Preview derivation copies source bytes. The fixed terminable PDF draft worker bounds parse/edit/save, rejects repeated/cyclic page trees and terminates on abort or deadline. The committed frame remains until a valid candidate is ready; explicit field navigation pans the existing viewport and yields to manual input. exportOperationId permits continuity only for a verified same-thread approved successful PDF export with matching grants and hashes. Denied or unrelated sources clear prior content. Preview never writes or exports; pdf_prepare and native approval remain necessary. No OCR, certificate signing or email is provided.

Diagnostics, ChangeSet, ApiExplorer and Pipeline accept {dataBinding,stateKey,actionId?,actionLabel?}. Their bounded source shapes and examples live in [packages/ui-catalog/software-development.ts](../packages/ui-catalog/software-development.ts). Selection uses stable source IDs. Optional actions send the selected item through the existing broker; these components execute no test, file change, HTTP request, build or deployment. Diagnostics/Pipeline check statuses distinguish not-run, running, passed, failed, skipped, blocked and unknown; file-change statuses and API response codes remain separate contract data.

ImageCompare accepts {beforeResourceId,afterResourceId,stateKey,beforeLabel?,afterLabel?,title?}. It saves {percent:0..100,mode:"overlay"|"split"} under /values/<stateKey>, defaulting to 50% overlay. Both granted images must load before the pair appears. Source/grant identity changes clear the old pair. The immediate pointer/keyboard reveal and view switch do not alter source bytes.

WorkflowBoard, ArchitectureCanvas and TraceWaterfall accept {dataBinding,stateKey,actionId?,actionLabel?}. Their strict source contracts live in [work-objects.ts](../packages/ui-catalog/work-objects.ts). Each source supplies a stable revision. WorkflowBoard supports at most six lanes and 100 cards; its durable draft tracks sourceRevision and placements, requires an explicit reset when the source changes, and retains one prior source checkpoint. Its action submits only current move proposals. ArchitectureCanvas accepts at most six layers, 60 nodes and 120 directed edges, with saved selection and neighbor focus. TraceWaterfall accepts at most 200 spans in an acyclic supplied hierarchy, with saved filtering, collapse and zoom; missing timing stays unavailable. Node/span actions ask about the selected source identity. None executes an external workflow, deploys a service or starts live tracing.

## UI discovery and composition

- ui_discover({query?,details?,offset?,limit?}) returns a concise combined component/domain index with version, total and nextOffset when another page exists. query is at most 200 characters. Index pages default to 100 entries and permit limit 1–100; details:true defaults to four and permits limit 1–8. offset is a nonnegative safe integer. Detail entries include schemas/examples; a relevant query or matched component also selects its named data pack (softwareDevelopment, everyday, interactions, exploration or workObjects). Exact ApiExplorer, Pipeline, ReviewQueue and EditableTable queries therefore return their source dataSchemas with details:true; the cheap index still omits them. Keep the same query and detail mode when paging. The response includes presentation/planning guidance, bounded-memory metadata and generatedApps {available:false,reason}; it does not repeatedly embed all schemas or widget runtime/style metadata.
- ui_inspect({artifactId?,requestId?,operationId?,dataId?,revision?,pointer?,offset?,limit?}) first returns the active thread's metadata, current plan, note keys/revisions and counts. SQLite projects metadata without loading full artifact specs, data values or operation output. Summary lists retain at most 20 entries each and shrink toward an 8 KiB response; counts and truncated identify omitted detail. Supply artifactId for its exact spec and current user state, requestId for the exact question, or operationId for exact operation evidence. Those explicit detail responses retain their full contract and are separate from the summary budget.
- ui_inspect with dataId reads same-thread saved data, including plan:<threadId>. Supply revision to pin the source while paging; omit it only to choose the current revision. pointer is a JSON Pointer relative to DataRecord.value, at most 2048 characters. Arrays default to 30 items, permit limit 1–100 and stop before the source-page byte budget; strings default to 2000 and permit limit 1–4000 UTF-16 code units, reducing the slice as needed. nextOffset resumes a page. An oversized object or single array item returns tooLarge and a narrower-pointer hint; full source data remains stored. For knowledge_publish's {title,value,sources} wrapper, /value selects the supplied knowledge object. See [task-inspection.ts](../packages/core/task-inspection.ts) for the exact bounds.
- ui_present creates or evolves a structured object from a complete spec or an existing object's bounded patches. ui_create_widget declares HTML/classic JS plus input/event/state schemas, but currently fails closed with CAPABILITY_UNAVAILABLE.
- ui_arrange uses artifactId/baseRevision and inline/expanded placement. Keep stable artifact IDs and state keys as work develops.
- ui_request_input accepts {commandId?,requestId?,baseRevision?,title,prompt,responseSchema,artifactId?,basis?,presentation?}. Without requestId it creates a durable decision. An update supplies that pending request's ID/current revision and preserves its response schema and existing option IDs; omitted basis and presentation are retained. presentation follows [PlanningQuestionSchema](../packages/contracts/planning-question.ts): options:[{id,label,description?,explanation?,examples?:[{text?,resourceId?,alt?}]}], allowCustom?. Option questions use a string response schema; every option must validate, and custom options cannot use a closed enum/const schema. Example resources must belong to the thread. The same request keeps its selected draft through detail-only revisions. Neither its response nor an explanation request approves an operation.

The presentation policy follows [generated-interface-brief.md](generated-interface-brief.md): compact task text, contextual controls, short sourced status and progressive evidence disclosure. It composes reusable mechanics from the actual task rather than choosing a fixed full screen by category. Synthetic captures do not prove agent composition or visual acceptance.

## Thread memory

task_memory({action:"list"|"save"|"delete",key?,content?,baseRevision?,commandId?}) reads or edits reminders scoped to the active thread. list returns notes and their revisions. save/delete require the inspected baseRevision; use 0 to create an absent key. Keys contain 1–64 letters/digits/periods/underscores/dashes, starting with a letter or digit. Content must be nonempty, with at most 768 UTF-8 bytes. The thread holds at most 12 notes and 4096 bytes for the serialized key/content collection. Obvious credential patterns are rejected; credentials and raw logs do not belong in notes.

Edits fail with STALE_MEMORY rather than overwriting a newer note. Delete retains a revision tombstone so recreating the same key advances its revision; an old editor cannot overwrite the recreated note. User edits use memory.save/memory.delete and share the same checks. The workspace Usage tab exposes inspect/edit/forget controls, retains failed-save drafts and shows a newer saved note for conflict recovery. Optional commandId provides host command replay semantics for agent writes.

The host includes saved key/content notes when starting a new run, including resumed or post-compaction work. Pi receives them explicitly as untrusted reminders, not instructions, source evidence, resource grants or approval. Existing artifacts, data and successful operation receipts remain authoritative. This is bounded per-thread continuity, not cross-thread learning. [task-memory.ts](../packages/core/task-memory.ts) is the source of truth for byte and revision checks.

## Plans and read-only delegation

[packages/contracts/planning.ts](../packages/contracts/planning.ts) exports PlanRecordSchema, PlanUpdateSchema, DelegateSchema, AgentProgressSchema, PLANNING_PROVENANCE and planDataId(threadId). PlanRecord {version:1,title,steps,agents} is stored as the existing DataRecord plan:<threadId> with provenance harness:plan. Steps retain IDs, statuses, requirements and optional assigned agent IDs. No new database migration or transport is required.

- plan_update({title,steps}) updates user-facing steps and acceptance requirements; agent execution fields remain host-owned.
- task_delegate({commandId,tasks:[{id,name,task,prompt,stepId?,requirements:[{id,label}]}]}) launches one to three readers with the parent's selected subscription model and read-only grants. The tool awaits all terminal results and streams actual job/usage updates into the plan. There are at most 24 retained jobs per thread.
- agent_progress({completedRequirementIds?,reportedPercent?,summary?}) is auxiliary-reader-only. Declared checklist completion determines its ring percentage when a checklist exists; otherwise an explicit reported estimate or null is used. Elapsed time never manufactures progress.

The coordinator in [packages/core/planning.ts](../packages/core/planning.ts) exposes updatePlan, delegate(ctx,args,signal), progressFromChild, inspect, cancel, recover and dispose. Child tool/publication callbacks retain the original parent authority and abort signal. Allowed readers are repository_files/read/status/diff/log, text_import and knowledge_publish. Mutations, operation preparation/execution, user requests, UI publication and nested delegation are denied. A child's task_finish cannot finish the parent; settlement alone is not successful completion. Actual source publications attach up to eight evidence {id,revision} references to the job, with evidenceTruncated when bounded.

Identical completed commandId retries return the prior batch result; concurrent pending retries share it. Reusing that ID with another payload is rejected. Restart leaves unfinished jobs interrupted and does not rerun them; new work needs a new explicit ID. Parent Stop/failure/disposal cancels original child contexts, including startup. These limits do not create an OS sandbox for approved project test code.

## Usage display

RuntimeUsage supplies nullable contextTokens/contextWindow, inputTokens/outputTokens, cost, sessionPercent and weeklyPercent. The live footer and workspace inspector show only reported values, not inferred billing or subscription balances. settings.update {preferences:{showUsageFooter:false}} disables the footer; older settings receive the true default while retaining their model/theme. Plan status/progress is distinct from subscription allowance. API-key billing fallback remains disabled.

Plan automatically presents the current thread's validated plan without moving composer focus; its height follows content. Closing dismisses that plan until materially new work arrives, and Thread options → Show plan reopens it. Live Usage starts closed; showUsageFooter enables its launcher and tool rather than forcing an open window. Closed tools reserve no conversation width. Both tools move vertically and reset position; manually sized tools use Shift+arrow keys on the move handle without a resize glyph. Narrow windows allocate a bounded tool area only while open. Native surfaces share durable identities and use source-display placement, DIP bounds, explicit display moves and disconnect rescue/restoration; see [native multi-monitor behavior and verification limits](native-multi-monitor.md).

## Subscription admission

[packages/contracts/connections.ts](../packages/contracts/connections.ts) exports four SUBSCRIPTION_OAUTH_PROVIDER_IDS (openai, openai-codex, github-copilot, xai), two SUBSCRIPTION_PLAN_PROVIDER_IDS (kimi-coding, opencode-go) and three OFFICIAL_RUNTIME_PROVIDER_IDS (claude-code, gemini-cli, cursor-sdk). SUBSCRIPTION_PROVIDER_IDS combines the six Pi connections; ConnectionProviderId includes all nine canonical IDs, while isConnectionProviderId also enforces the manifest's available status. Availability means a source integration exists, not that the local profile is signed in, entitled or live-tested. Cursor is a preview with the [documented native/offline acceptance boundary](plans/cursor-subscription-adapter-20261031.md). Historical executables retain their recorded inventories.

The unified [runtime-login entry point](../packages/runtime-login/index.ts) and narrow desktop bridge validate an allowlisted connection ID and fixed arguments. Provider secrets are entered in the native connection console, not passed as executable arguments or ordinary renderer commands. Pi credentials stay under dataDir/pi/auth.json. Official runtimes sign in directly under dataDir/official/<provider>/home with a deliberately isolated environment; Pi OAuth and existing external CLI profiles are not reused. Harness-owned official, pi and artifacts paths are denied through both task-grant validation and the native guarded I/O path.

Pi uses the app-owned [LiteralCredentialStore](../packages/runtime-pi/credentials.ts): reads parse literal data without SDK !command/environment expansion, while writes and OAuth refresh retain the pinned SDK's native locks. The four OAuth definitions omit API-key resolution. Plan keys require an explicit per-provider HARNESS_CONNECTION_KIND marker, 1–4096 visible ASCII characters, no whitespace, leading ! or $ syntax, and matching stored credentials at use. Environment keys, unmarked legacy keys, custom endpoints and other providers cannot become app-side billing fallback. An unavailable Kimi connection does not suppress healthy configured providers during discovery.

[plan-keys.ts](../packages/runtime-pi/plan-keys.ts) pins Kimi to https://api.kimi.com/coding/v1 with authenticated bounded /models validation (ten-second deadline, 256 KiB, at most 2048 unique IDs) and an intersection with installed models. Its connection is for personal interactive coding. Go pins OpenAI Chat Completions/Responses to https://opencode.ai/inference/go/openai/v1 and Anthropic Messages to https://opencode.ai/inference/go/anthropic. Requests require the exact admitted POST endpoint, reject redirects and replace credential/identity headers. Go requires a stable conversation session ID. The Google SDK transport is excluded because this adapter cannot enforce its redirect policy. Installed Go models and connection markers do not prove account entitlement. No Moonshot or Zen/pay-as-you-go endpoint is substituted.

These controls prevent app-side fallback; they do not guarantee zero charges. Provider-side Extra Usage can still use an account/Console balance at the fixed plan endpoint. Unknown cost/quota telemetry remains unknown. The OpenCode agent runtime is separately pending and Meta/Muse remains unavailable. See [subscription-connections.md](subscription-connections.md) for current provider boundaries and primary sources.

## Runtime composition

[packages/runtime/index.ts](../packages/runtime/index.ts) exports createRuntime({dataDir}): RuntimeAdapter. Both the primary [server host](../apps/server/host.ts) and [planning coordinator](../packages/core/planning.ts) instantiate this composite adapter. It routes claude-code/* and gemini-cli/* model IDs to createOfficialRuntime and other admitted models to createPiRuntime. Session paths must belong to the current profile and matching runtime; changing runtime for an existing session requires a new thread. Run ownership is pinned to threadId/runId/epoch, checked before and after host tools, and revoked on settlement/cancel/disposal. Healthy provider results remain discoverable if another adapter fails.

RuntimeAdapter exposes configure(callbacks), models({refresh?}?), start(input), followUp(input), cancel(ctx), compact(ctx,sessionPath,modelId), history(sessionPath) and dispose(). StartRun carries modelId, optional thinkingLevel:string|null, sessionPath, inputId/inputIds, prompt, resource grants and optional untrusted thread memory. Model discovery caches successful results and shares concurrent lookups; refresh explicitly reopens discovery. No model list alone proves live inference or subscription entitlement.

### Pi adapter

packages/runtime-pi/index.ts exports createPiRuntime({dataDir}): RuntimeAdapter.
Parent callbacks receive onTool and onEvent. Use shared interfaces; tool catalog comes from packages/runtime-pi/tool-definitions.ts and can be self-contained until capabilities metadata exists.
Events: assistant.delta {messageId,delta}; assistant.message {messageId,content,inputIds}; input.processing {inputIds}; activity {message,toolCallId?}; session {sessionPath}; usage {usage:Partial<RuntimeUsage>}; settled {aborted}; error {message}; compaction.start/end. Every event includes original RunContext. input.processing identifies actual SDK user-message entry; assistant.message identifies only inputs processed by that response. Settlement revokes that runtime authority and never acknowledges unrelated queued inputs. Tool results must await root onTool.
history(sessionPath) returns persisted application input IDs from envelope markers. Never infer durable delivery from an in-memory queue callback.

### Official adapters

[packages/runtime-official/index.ts](../packages/runtime-official/index.ts) exports createOfficialRuntime({dataDir}): RuntimeAdapter. Pinned dependencies are Claude Agent SDK 0.3.316 with published native Claude Code 2.1.316, Gemini CLI 0.66.0 and MCP SDK 1.32.2. The harness resolves published installed distribution entries rather than PATH commands and leaves native authentication methods intact. New source/package acceptance is separate from the existing v0.3 delivery.

Each official run owns a random authenticated loopback [host MCP endpoint](../packages/runtime-official/mcp.ts). Only the registered host tools reach the original parent callbacks; run authority is checked before and after tool execution. Native shell/file/agent task tools are not added as execution authority. Stop and failure close MCP, drivers and tracked native processes, and await owned manifest writes. Per-connection settings/prompt paths prevent concurrent discovery or reader startup from overwriting another connection's configuration.

Claude checks native account metadata before task input and rejects API-key, third-party and unknown contexts for this subscription connection. The published binary's sign-in methods remain unchanged. Models and supported effort levels are native-advertised. Explicit effort uses the SDK flag API; null selects native default semantics. Advertised /compact support is insufficient alone: completion also requires a native compact boundary and successful terminal result.

Gemini negotiates ACP v1 and Google-account authentication, obtains the fresh advertised model list and rejects an unadvertised selection before input. An existing native session continues through --resume and --output-format stream-json after fresh ACP preflight. [Native history](../packages/runtime-official/gemini-native-history.ts) validates canonical project mapping, project-root marker/hash, exact session identity and leading application input markers. Headless user echo alone is transport evidence, not a receipt; current-turn work/terminal evidence or matching native history establishes consumption. Current-turn output is validated through process close so stdout is drained, rather than settling early at process exit or replaying prior assistant output.

Gemini compaction is unavailable in this pinned runtime. Actual ACP does not advertise /compress, and native headless continuation has no verifiable compression result; compact fails with OFFICIAL_COMPACTION_UNSUPPORTED. A positive capability-gating test uses a synthetic future advertisement and does not establish native support. Live account login, task inference, native compaction and freshly packaged provider expansion remain outside the current source/empty-profile verification.

## Widget bridge
The parent owns token/mount identity. Its controller fetches only /widget-runtime/worker.js, the fixed import-free IIFE, with credentials:'omit' and redirect:'error'. It relays the bytes to a fixed, hashed receiver under sandbox allow-scripts, which starts an opaque-origin data worker. That worker inherits WIDGET_SHELL_CSP; the fetched asset's HTTP WIDGET_WORKER_CSP is defense in depth, not the opaque-origin boundary. Native persistence is denied by origin and network by inherited CSP. No generated JavaScript runs in the host or receiver. Only bounded validated DOM snapshots reach the receiver. unsafe-eval supports classic execution inside the worker.

Parent sends {channel:'harness-widget',token,mountId,artifactId,type:'init',inputs,state,theme}. Child bridge messages carry the same identity with type ready/checkpoint/action/dirty and payload. Validate event.source against the current iframe WindowProxy, all identity fields and the declared schemas. Checkpoint acknowledgment follows host acceptance; never promise durability for unacknowledged state. Draft journaling uses synchronous localStorage write-ahead staging before IndexedDB and generation compare-and-swap against stale acknowledgments; synchronous-storage failure leaves the awaited IndexedDB path.

Host-owned WIDGET_BASE_CSS in packages/widgets/theme.ts supplies task classes and theme tokens. Generated apps remain gated off until final acceptance. The worker/watchdog and accepted-message limits provide no hard memory quota. See [packages/widgets/README.md](../packages/widgets/README.md) for exact APIs, integration and limits.


Request actions carry the host-pinned `requestRevision` returned by inspection. Explicit republication may bind a current decision; unrelated artifact updates retain the original binding. A changed/consumed decision or a legacy action without a pinned revision fails closed, without accepting submitted state. Native `request.respond` still uses its displayed revision. Pi's strict action schema supports round-tripping this field.

Backend PDF inspection and preparation/export run in a resource-limited, terminable worker, with a 15-second deadline and the task AbortSignal. Input/output are bounded to 32 MiB, page/form trees are checked before expansion, and inspection data is limited to 2 MiB. Supported limits are 200 pages, 500 fields and 100 edits. These limits are explicit failures, not silent document truncation. Worker heap limits are not hard external-memory isolation.
