## Implemented contracts carried forward

### Sources, pointing and retained bytes

`SelectedSourceV1` is a strict MESSAGE, FILE_RANGE, DIFF_HUNK or ARTIFACT_REGION union. The host checks complete logical ownership, account binding, revision, content digest and grants at capture/read/send/recovery boundaries. Message ranges are half-open UTF-16 and reject surrogate splits. File lines are one-based and inclusive. Artifact pointers accept declared data bindings and canonical safe in-bounds array indices, not JavaScript array properties.

Selection actions require registered React roots, exact canonical text and visible ranges. Forged attributes, hidden/clipped descendants, inputs, links, foreign panes and arbitrary iframe content cannot create authority. Formatted Markdown has no trusted inline offset map, so an exact per-message canonical selector is the supported fallback, including messages outside the bounded catalogue. Ask does not overwrite authored text or send implicitly. Attach stores bounded source context; Open returns exact retained bytes. Preview, range, revision, capture time, destination, Remove, Refresh and explicit Keep make source identity visible.

The bounds remain eight draft references, 64 persisted presentation entries, a 1 MiB source, 64 KiB selected capture and a 1,024-byte preview. Source context grants no file/tool access. FILE_RANGE remains unsupported on the local Linux leaf reader and requires real Windows evidence. DIFF_HUNK capture remains disabled until its owning service supplies an atomic complete-comparison witness.

### Admission, recovery and durable drafts

NOW and AFTER_CURRENT use the existing `message.send` outbox and M04 request custody. A pending attempt freezes command ID, prompt, owner, model, source identities, delivery mode and generation. Matching in-flight admissions coalesce; durable receipts take precedence over a later eligibility rejection. Proven precommit rejection unlocks edits, while an uncertain outcome retains the exact retry. Old acknowledgments cannot clear newer text or source generations.

The C2 first-account repair is retained: a provably unbound empty task can acquire one host-owned admission witness atomically with first accepted input, without changing captured references, bytes, digests or grants. Legacy, foreign, changed-account or changed-epoch custody cannot silently rebind. M04 rollback first proves that no matching command receipt or outbox row committed, then restores only the exact admission advances and newly acquired claim. Accepted, finalized, replaced or newer custody cannot be reopened. These are inherited repairs whose C3 execution status is recorded separately.

Accepted inputs can be inspected, explicitly kept or cancelled only when the host proves they are persisted and undispatched. Keep requires ordinary explicit Resume. Runtime/processing ambiguity blocks cancellation. Recovery checks the complete saved input and ownership around asynchronous work. Lost acknowledgments retain the exact local recovery ID/action, including cancellation whose input has disappeared. Local retry state is not task authority.

Saved drafts retain bounded source companions. Source-bearing transfer uses version 2; ordinary text remains compatible with version 1. Text-only restore is explicit and preserves active source context. Multi-key journal CAS, owner/account/epoch generation fences and conflict copies protect newer drafts and A-to-B-to-A transitions. Handoff waits for durable writes; uncertainty preserves recovery data. Composers without source integration reject hidden source companions rather than dropping them.
