## Additional recovery repairs found by review

Source-aware precommit rejection now distinguishes a proven unaccepted send from an uncertain delivery. Matching command receipts and in-flight admission coalescing prevent a retry from falsely claiming rejection while another admission can commit. A rejected draft remains editable; an ambiguous send retains the exact command and sources.

Accepted queued inputs are no longer stranded when their source becomes stale before runtime entry. The host exposes inspect, KEEP_CAPTURED and CANCEL only for the exact owned input. Keeping retains identity and requires ordinary explicit Resume. Cancellation is restricted to proven undispatched persisted inputs. Both paths recheck against concurrent preparation. A local recovery command record preserves its exact ID/action through lost acknowledgment, including cancellation whose input disappears from the queue before its receipt reaches the browser.

Named drafts and export/import retain bounded source context. Source-bearing exports use a new format version so an older reader cannot silently discard citations. Named-draft restoration is explicitly text-only and preserves the current source context. Modal failures use role=alert; focus restoration waits for the dialog to commit closed.

C2 first-send admission now records a host-owned account-custody witness while retaining the original captured reference, bytes, digests and grants. Real host artifact fixtures cover an empty task, M04 enabled/disabled, account-discovery races, rollback/retry, legacy captures and changed-account rejection. The previously reported first-account defect is therefore repaired in source; first-file native proof remains a separate gate.

Default-off rollback retains source inspection and removal under the current code. Binary downgrade to `fd17d9f1` does not understand the new `sourceAccountAdmission` proof and can fail closed; legacy captures are never silently promoted into authority. Default-off rollback coverage is not a binary-downgrade compatibility claim.

M04 rollback now restores only exact custody transitions from a proven uncommitted send, after checking that neither a command receipt nor its outbox row committed. It cannot reopen accepted, finalized, replaced or more recently advanced custody. The immutable review and red/green records are in `m15-artifacts/c2-m04-admission-review-01.json`. Hermes startup cleanup now distinguishes a guard that was never acquired from uncertain release or process teardown after acquisition. Current focused coverage includes both repairs, while actual Windows engine execution remains pending.
