# Original-requirement matrix

This matrix maps the uploaded v3 prompts and relevant research to implementation and evidence. Input identities and the overall conclusion are in the [audit report](../M04-M06-review-20261117.md). E01 through E22 refer to the [evidence ledger](evidence.md). Code links point to the immutable combined candidate, which is NOT_RUN as a whole; focused test claims retain their separate source cuts.

The row identifiers are audit identifiers. Requirements are paraphrased and grouped. `Implemented` means a production path was identified. `Verified in scope` means recorded tests exercised that path or invariant, not that the release is verified. `Partial` means required code or composition is missing. `NOT_RUN` means execution evidence is absent. `Optional` identifies an experiment that can remain disabled. Default-off activation is separate from these statuses.

## Release interpretation

An absent production caller is an implementation gap. An implemented path with only scripted, fixture, or protocol evidence still needs its runtime/platform/provider gate. An optional experiment may remain disabled. Default-off flags resolve neither required implementation gaps nor missing acceptance evidence.

This matrix preserves failures and historical receipts, credits focused repairs only within their source/evidence scope, and leaves all required unexecuted gates visible. **No full release signoff is granted.**
