# Context7 SecretRef composition

The existing personal Context7 configuration and installed Node destination are the scope. The `security.secretRefsV1` host flag remains off by default. Disabled or unconfigured metadata performs no credential or executable lookup. Public status contains one opaque current reference, its purpose, owner and process-environment destination, or a bounded generic unavailable reason. Executable observation is metadata, not native execution proof.

The metadata foundation invalidates the current reference before configured-child drain and rotates it after key or executable identity changes. It blocks the existing unapproved credential callback when enabled. It creates no approval and delivers no secret. The existing unflagged child configuration remains available.

The following consumer change must expose `integration_prepare` through the actual host tool registry, prepare an existing Operation, and require its explicit authenticated approval. The approved action binds the reference identity, executable and entry bytes/identity, manifest, argument vector, cwd, request, and owner. The executor must reacquire native path custody and revalidate before resolving a single-use destination-bound reference, then release its temporary MCP session. Failed or unavailable native custody remains a denial; Linux test fixtures do not establish Windows native proof.

The settings metadata HTTP route and rendering are separate changes owned by the host/UI composition. No new key entry or reveal path is part of this work.

## Approved consumer

The consumer exposes the strict `integration_prepare` tool in SecretRef mode and routes it through Service's host-owned preparation hook. Its pending Operation binds the request, current owner/model, opaque reference, actual executable/entry/manifest/package metadata, argv, cwd identity and preparation-schema digest. The existing user approval command creates authenticated authority; the executor verifies the current operation and owner again under native path custody before issuing the one-use SecretRef delivery. One temporary MCP session handles one approved request and is drained before native custody is released. Known credential output is redacted before Store/model delivery. An observed child spawn remains recorded after teardown, so loss, revocation or Stop during a request leaves an uncertain outcome rather than a false failure receipt.

Production uses the existing namespace guard without a fallback. Positive Linux composition fixtures substitute only that native lease and use a real owned copy of Node, real Store/Service/signing, and a real stdio MCP child. A separate test uses the actual Linux guard and requires denial before launch; actual Windows native cases are separate acceptance evidence.

Development pnpm hardlinks are not the installed-runtime contract. Existing `stageRuntimeInstall` in `scripts/desktop-assets.ts` selects hoisted dependencies with `package-import-method=copy`, frozen offline installation and disabled package scripts. `scripts/package-desktop.ts` copies the checksummed Node distribution; `scripts/integration-assets.ts` checks packaged Node files against the existing `NODE_LOCK.json`. This change does not alter that packaging policy, install dependencies, activate flags or establish installed Windows acceptance.
