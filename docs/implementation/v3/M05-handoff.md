## Deletion storage, migration and restore

The authoritative fence is a sibling of the canonical profile: `.gen-memory-deletions-<sha256(canonical-profile-path)>.jsonl`, case-normalized on Windows. A `project-memory-deletions.jsonl` mirror remains inside the profile. [Storage protection](../../../packages/core/security.ts) blocks direct/ancestor grants, reserved peer-profile fence names, symlinks and ordinary-name hardlink aliases. `projectMemoryLedger` enrolls the authoritative path, device and inode. Missing, replaced or unsafe enrolled storage fails closed.

Forget fsyncs that fence before its local mirror and SQLite mutation. It survives SQLite-only restore and in-place restoration of profile contents when the parent fence and physical profile enrollment survive. Startup reconciles restored items/sources, recomputes collateral artifact dependencies and reopens pending purge. Failed enrollment remains incomplete until a successful retry. Source-only replay cannot retain an obsolete COMPLETE acknowledgement.

The guarantee assumes the authoritative fence survives. Whole-parent/system rollback can roll it back too. An unsandboxed same-user process can bypass application grant checks. No external monotonic anchor or operating-system sandbox protection is claimed. Recreated profile/project identities do not automatically inherit authorization.

Source exclusion is digest-based: another claim with the same source bytes becomes unavailable and its derived artifacts are invalidated. Original files/task history remain. Minimal IDs, references, counts and digests can remain in receipts; memory prose and plaintext match terms are not copied into them.

### Exact migration

1. **Enable secure deletion before retention.** Initialization sets SQLite `secure_delete=ON` before memory writes. The published pre-continuation implementation enabled it only during purge, which could not erase text freed by earlier updates.
2. **Rebuild legacy free pages once.** If `projectMemoryStorageFormat/secure-delete-v1` is absent and legacy `projectMemory*` entities exist, initialization performs host-owned `VACUUM` outside Store callbacks, then `wal_checkpoint(TRUNCATE)` with a nonblocking busy check. The marker commits only after success. A pinned reader/failure leaves M05 unavailable and the marker absent. A restored pre-marker backup reruns this migration.
3. **Separate migration cost from bounded purge.** VACUUM rewrites the live database and can need time/free space proportional to its size. This one-time operation is not limited to 256 rows and has no claimed latency benchmark. A new profile without legacy memory does not require that rebuild.
4. **Additive logical schema and enrollment.** Scoped `CREATE INDEX IF NOT EXISTS` indexes and separate entities leave task-note content, Hermes skills, native history and strict preferences intact. Existing source history is not automatically imported. Opt-in requires host activation, authenticated source selection and durable deletion-ledger enrollment; legacy local deletion records carry forward. There is no new package dependency or lockfile migration.
5. **Bound ongoing deletion.** After seven days, maintenance uses a bounded item batch and deletes at most 256 entity rows per call through scoped indexes. The host retries every minute. Items, revisions, conflict/use projections, excluded source copies and affected derived indexes are removed. Tombstones, ledgers, consent, numeric usage metadata and original source history remain. A reader holding old WAL pages keeps purge pending.

### Operational rollback

Disable `memory.projectV1` and leave `memory.externalRecallExperimentV1` false. Fresh injection, extraction and required M05 checkpoint admission stop. A prepared selection loses its final consent check instead of dispatching silently after disable. Authenticated review and permitted retained-record edits remain available under current source/revision checks; new opt-in is refused. Project disable does not require an obsolete source to become eligible again.

Preserve the entities, secure-storage marker, authoritative sibling, mirror, enrollment and storage protections. Tombstones and purge remain active while the flag is off. Existing thread notes provide the fallback without copying M05 claims into notes or Hermes skills. Removing fences, restoring the whole parent storage tree or reverting to code that ignores deletion custody is outside the validated rollback procedure. Disable does not erase existing provider/native history.
