## Source and permission limits

Logical ownership comes from the exact task/thread, project, working-copy workspace and account/epoch boundaries. Canvas IDs, split panes, presets, local retry records and active global presentation state cannot create or rebind source authority. Retained legacy layouts remain parseable without reviving removed hosts. A generic files/diff/output panel does not imply an atomic capture capability.

The first-account witness changes account custody only for host-proven unbound captures and is written in the same transaction as admission. M04 rollback checks absence of both matching durable receipt and outbox commit before undoing exact transitions. Acquired native guards and uncertain process teardown remain failures rather than being suppressed as startup denial. These C2 fixes remain documented as inherited behavior, with C3 verification in the ledger.

Default-off rollback retains inspection/removal, ordinary NOW reset, proven-undispatched cancellation, messages, captures, evidence, saved drafts and ambiguous retries. It means disabling the feature while retaining current code. It does not establish binary-downgrade compatibility; cut 1 `fd17d9f1` lacks the later admission witness and can fail closed. Legacy material cannot be promoted into authority to hide this limit.
